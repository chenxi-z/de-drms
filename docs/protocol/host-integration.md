# 上位机接入指南

供上位机开发者和接续工作的 agent 使用。固件与上位机独立开发，当前尚无上位机程序。本文概述设备工作流及接入现状；消息号、类型、单位、CRC 和测试字节以[CDC v2 协议](de-drms-cdc-v2.md)及[机器定义](../../shared/protocol/de-drms-cdc-v2.json)为准。

## 设备规划与现状

- **使用场景**：双电极电阻监测，依据用户主动建立的基线 R₀ 计算 R/R₀，再按试件的区间配置判断等级。客户阈值和基线稳定容限需要实测标定，不应由客户端臆造。
- **本机交互**：设备没有显示屏，使用两个按键和五个 LED。开机自动监测，不自动记录；无卡仍可监测，有可用 TF 卡才可开始记录。按键和 CDC 均可发起记录，结束后继续监测。USB 断开不应自动终止本机记录。
- **本机验证过的固件能力**：CDC v2 支持握手、状态/操作/记录查询、开始和结束记录、配置读取与修改、基线、参考校准、校时、文件列表和下载、MSC 导出/交还、安全停止和恢复监测；具体条件和异步结果以[协议现状](de-drms-cdc-v2.md)为准。模拟测试通过不等于板卡实测通过。
- **尚未接通**：实时曲线/原始流的订阅和自动推送、故障事件优先发送、USB 固件升级。测量事件目前只有编码器；客户端暂用 `GET_STATUS` 轮询，依据新鲜度和有效标志显示结果，不能把旧等级当作当前状态。
- **存储互斥**：记录期间不下载历史文件、不导出 MSC；MSC 导出期间继续监测但不能开始记录。本机和上位机共用同一张卡的所有权由固件裁决，客户端应处理 BUSY、失败和介质代次变化。
- **实物仍需验证**：USB 枚举与拔插、TF 卡读写和持续吞吐、采样完整性、模拟精度及 SRAM4 使用等。协议能力或软件配置成功不代表实测性能达标。

## 客户端工作流

| 工作流 | 客户端责任 |
| --- | --- |
| 接上设备 | 打开 CDC、置 DTR，发送 HELLO。读取硬件身份、启动标识、会话和能力列表，再用 GET_STATUS 建立初始视图。相同设备可多次重启，端口名不能作设备编码。 |
| 打开已有试验 | 按快照中的 record 查询 GET_RECORD。允许记录来自物理按键。进入界面只是观察，不隐式开始、停止或接管试验。 |
| 发起或结束记录 | 分别用 BEGIN_RECORD、END_RECORD；结束请求携带目标记录号。保存请求编号和返回的操作、记录标识。受理后按事件或 GET_OPERATION 查结论；GET_RECORD 查整场试验。显示文件关闭情况和采样损失两项结果。 |
| 超时、重连 | 同会话内原编号重发必须保持内容一致。重连先握手、查快照，比较启动标识。确认同一次启动后可按原业务标识查询，先前未收到回复的启动动作不能自动重放。订阅按新会话重新建立。 |
| 显示读数和曲线 | 当前通过 GET_STATUS 读取有效电阻、基线、区间状态和新鲜度；过期时撤销正常等级。将来订阅接通后按能力和返回周期运行，保留缺口和代次变化。 |
| 修改配置 | 先读完整配置及版本，带期望版本提交修改。分别展示运行版本和已保存版本；版本冲突先重新读取。记录期间配置修改会被拒绝。 |
| 取历史文件 | 记录空闲时用 FILE_LIST/OPEN/READ/CLOSE，按介质代次校验、绝对偏移读块；或显式 MSC_EXPORT/RELEASE 交接只读磁盘。解析内容按[BIN 文件规格](../design/2026-11-06-record-v2-format.md)识别版本。 |

联调可先用机器定义里的四条向量核对编解码，再回放一条“设备已由按键开始记录”的状态序列，覆盖中途连接与重连。真实 USB 枚举、DTR、拔插及磁盘交接须与支持对应能力的固件联测。现有 ASCII 调试口不能用于验证 v2 互通。

进一步了解业务需求和交互，可阅读[设备行为与验收](../spec/device-behavior.md)；了解记录文件解析，可阅读 [BIN v2 格式](../design/2026-11-06-record-v2-format.md)。固件内部线程与模块规划见[固件架构](../design/2026-11-05-firmware-architecture.md)，其中目标设计不能直接当作已交付能力。
