# 上位机曲线显示规格（草案）

日期：2026-11-14。状态：**曲线显示口径已定，其余仍是草案**。
接续 [2026-11-13 上位机需求交接](2026-11-13-host-requirements-handoff.md)。

本文只规定"曲线画什么、怎么画、哪些不能画"。技术栈、界面框架、打包路线仍未选定。
文中所有设备行为均按 2026-11-14 工作区源码核对，引用处标出文件与行号；

## 1. 用户已确认

| 项 | 确认内容 |
| --- | --- |
| 慢测试典型时长 | 30 分钟 – 1 小时 |
| 最小可辨变化 | ≤ 0.1 秒 |
| 曲线纵轴 | **主图 R/R₀，副图 R**（两者都要显示） |
| 主图默认单位 | **绝对比值**（可切换到百分比偏移） |
| 平滑 | **需要**，用通用方式（滑动平均），详见 §9 |
| 绘图风格 | **接近 MATLAB** |
| 建立 R₀ | **提供按钮**，详见 §11 |

"主副"指重要性与版面位置，不表示可以互相推导——见 §3.3。

## 2. 两个数据源，不可混画

| 源 | 内容 | 时间分辨率 | 用途 |
| --- | --- | --- | --- |
| CURVE 订阅（`SUBSCRIBE` stream=CURVE → MEAS_EVENT，opcode 130） | 降速后的最新快照 | 100 ms 起（`period_ms` 下界） | 联机实时观察 |
| BIN 文件（v2 格式） | 全量原始帧，16 B/点 | 4 kSPS = 0.25 ms/帧 | 事后分析、抓瞬态 |

**同一张图上不得混画两个源。**联机曲线是"发布时刻的抽样"，回放曲线是"每个采样点"，
两者点数、时间轴含义、噪声都不同。界面必须明确当前处于联机模式还是回放模式。

### 2.1 联机曲线抓不到 0.1 秒瞬态

`SUBSCRIBE` 的 `period_ms` 只拒绝 `0` 和 `>60000`（`App/interfaces/cdc/drms_cdc_v2.c:367`），
实际可用下界是 100 ms（台架实测 100/200/500/1000 ms 四档）。
MEAS_EVENT 携带的是 `drms_application_snapshot()` 的最新快照，
代码注释明确写着"不是原始流，全速数据在记录文件里"（`drms_cdc_v2.c:138`）。

**结论**：联机曲线能看清的是"每秒 10 个点"的趋势，**不能承诺捕获持续时间 <100 ms 的瞬态**。
要判断加载瞬间的跳变，必须靠 BIN 事后分析。

界面必须在曲线区标注"联机曲线为 100 ms 抽样，非全量"，不能让人把曲线当证据。

## 3. 纵轴

### 3.1 三个量的口径

| 量 | 协议字段 | 计算方式 | 需要什么 |
| --- | --- | --- | --- |
| R | `ohms`（tag 23） | **单帧** `scale × V_sample / V_Rsense`，未滤波；发布前量化到 **1 mΩ** | 采集运行 + `excitation_ok` + `fresh` |
| R/R₀ | `ratio`（tag 24） | **滤波后** R ÷ R₀，即 `drms_filter_step()` 输出除以基线 | `fresh` **且** 分类状态 ≥ `UNMAPPED` |
| ΔR/R₀ % | 无 | `(ratio - 1) × 100`，**由上位机换算** | 同上 |

依据：`drms_application.c:1777-1781`（R 用 `latest` 单帧并量化到整数 mΩ）、
`drms_monitor.c:173`（ratio 用 `filtered`）、`drms_application.c:1848`（ratio 发布条件）、
`drms_application.c:1868`（`measured_milliohms / 1000.0` 还原为欧姆）。

### 3.2 R/R₀ 的隐藏门槛：必须有区间表

```c
next.ratio_valid = next.fresh && published_monitor.state >= DRMS_MONITOR_UNMAPPED;
```

`UNMAPPED` = 3，而区间表为空时 `drms_monitor.c:199-201` 强制 `state = DRMS_MONITOR_UNCONFIGURED`(=2) < 3。
所以：

- **只建了基线 R₀、没配区间表 → `ratio` 字段不发布，主曲线是空的**；
- 出厂空配置同样如此。

这改变"试验前检查"的内容：**曲线能不能画 R/R₀，取决于区间表是否配置，不只是基线**。
检查项必须区分"基线缺失"与"区间表缺失"。

### 3.3 R 与 R/R₀ 不能互相推导

三处差异使二者不是简单比例关系：

1. **平滑不同**：设计意图是 R 走单帧、R/R₀ 走一阶 IIR（时间常数 `tau_us`）；
   `tau > 0` 时 `ratio ≠ ohms / R₀`。**但见 §3.3.1：该滤波器当前实际失效**。
2. **量化不同**：R 发布前被量化到 1 mΩ（`int32_t` 毫欧），R/R₀ 是 f64 直通。
3. **R₀ 的来源不同**：基线由**原始** R 的统计量建立（`drms_application.c:1095-1105`
   用 `drms_resistance()` 的未滤波值喂 `drms_baseline_feed`）。

**因此**：图上不得提供"用 R 反算 R/R₀"或反之的功能；不得把两条曲线的变化幅度做数值比较。
需要比较时，只能比各自的变化率。

#### 3.3.1 固件 `tau_us` 滤波系数失效（HANDOFF F-1，2026-11-15 已修复）

**当前状态：已修复**（源码公式改为 `exp(-dt/tau)`，测试已补两条能抓住该 bug 的用例）。
本小节保留原始分析过程，供上位机判断"手上设备固件是哪一版"时参照：
**修复前的固件** R/R₀ 实际无有效平滑，界面不得声称"已按配置平滑"。

`App/application/measurement/drms_filter.c:36-37`（修复前）：

```c
double dt_us = 1000000.0 / (double)rate_hz;
ctx->alpha = 1.0 - exp(-(double)tau_us / dt_us);   /* 分子分母颠倒 */
```

标准一阶 IIR 应为 `alpha = 1 - exp(-dt / tau)`，代码写成了 `exp(-tau / dt)`。
后果（4 kSPS，dt = 250 µs）：

| 配置 `tau_us` | 正确 alpha | 代码 alpha | 实际等效时间常数 |
| --- | --- | --- | --- |
| 1 | 0.000004 | 0.003992 | 62.6 ms |
| 10 | 0.00004 | 0.039211 | 6.38 ms |
| 250 | 0.001 | 0.632121 | 0.40 ms |
| 1 000 | 0.004 | 0.981684 | 0.25 ms |
| ≥10 000 | 0.04 | **1.000000** | 0.25 ms（无滤波） |

两个性质：**参数大部分取值退化**（`tau ≥ 10 ms` 时 alpha 恒为 1.0，
配 10 ms / 100 ms / 1 s 输出完全相同）；**等效时间常数随采样率漂移**
（`tau=250` 时 1 kSPS → 4.52 ms、16 kSPS → 0.064 ms，差 70 倍）。

单元测试未能捕获：`test/test_monitor_pipeline.py:145` 只测 `tau=250`，
该点两种公式数值巧合接近；其余用例均为 `tau=0`（旁路）。

**严重性**：不影响 R 的测量正确性（`drms_resistance` 与滤波无关），
属于"配置项不生效"，不是精度缺陷。完整描述见 [HANDOFF.md 的 F-1 条](HANDOFF.md)。

**对上位机的影响**：

- 修复前固件下 R/R₀ **没有有效平滑**，噪声与 R 相当；
- 若用户配置了大 tau 期望平滑，实际得不到——**不得在界面上声称"已按配置平滑"**；
- 因此上位机的界面平滑（§9.1）**不是补丁，而是当前唯一生效的平滑**。
  即使固件修好，界面平滑仍有独立价值（可随时开关、不改变设备行为）。

**关于"算不算缺陷"**：从显示效果看，界面平滑确实可以独立解决"曲线太毛糙"；
但 `tau_us` 作为设备配置项，其语义（"时间常数"）没有兑现，
配置者会得到与预期不符的行为。这属于配置语义问题，不是绘图问题。
是否修由固件侧决定；本文档的上位机设计不阻塞于此。

### 3.4 `tau` 可能读不到

`tau_us` 来自 `GET_CONFIG`（tag 74）。出厂空配置时 `GET_CONFIG` 返回 `UNSUPPORTED`
（协议正文 §编码段），上位机拿不到该参数。

**处理**：读不到就显示"平滑参数未知"，不得默认为 0（旁路）或猜测某值。
界面级平滑独立于该值，见 §9.1。



### 3.5 版面

**上下双图，共享横轴**：

- 主图（约 2/3 高度）：R/R₀ 或 ΔR/R₀ %，叠加区间色带；
- 副图（约 1/3 高度）：R（Ω 或 kΩ）。

**不采用"单图双纵轴"**：R 与 R/R₀ 相差约 R₀ 倍，双轴会诱导读者做假相关；
两轴刻度独立性也会掩盖两者的噪声差异。

副图必须可折叠——判级只需要主图，副图是诊断用。

### 3.6 纵轴单位与量纲

- **主图默认显示绝对比值**（1.0 = 基线），可切换到百分比偏移 `(ratio-1)×100 %`。
  用户已确认默认比值；百分比偏移作为可选视图保留，因为判级阈值通常以百分比表述。
- 区间边界的 `lo`/`hi`（`DRMS_MonitorInterval`）**以 R/R₀ 为单位**，
  画色带时必须先换算成当前显示单位，不能直接当百分比用。
- R 建议用 kΩ 显示（量程 10–120 kΩ），避免六位数。

### 3.7 自动缩放

- 不得裁剪数据：缩放范围必须覆盖可见窗口内全部有效点；
- 区间色带不得因缩放而失真，色带只在配置区间覆盖的范围内绘制；
- 缩放/平移时纵轴可自动或锁定，但**锁定状态必须可见**，避免误读为"数据平了"。

## 4. 横轴

### 4.1 联机：只有 `mono_us`，且它是发布时刻

`next.mono_us = drms_acq_now_us()`（`drms_application.c:1825`）是**快照发布时刻**，
不是该帧被 ADC 采到的时刻。中间隔着采集队列与应用轮询（约 10 ms 级）。

- 分辨率 1 ms（`HAL_GetTick` 由 TIM7 1 kHz 驱动，`stm32u5xx_hal_timebase_tim.c:71`）；
- 与真实采样时刻的偏差约 10 ms。

100 ms 周期下这个偏差可接受，但**必须写进界面说明**，不能声称是采样时刻。

### 4.2 回放：能重建精确时刻

BIN v2 的 HEADER 带锚点（`anchor_sample_seq0` / `anchor_mono_us0` / `rate_hz`），
用 `capture_us = mono_us0 + (sample_seq - sample_seq0) × 1e6 / rate_hz` 重建
（`drms_capture_time.c:87-92`）。缺锚点（`generation=0`）时**不得**把样本序号映射成时间。

### 4.3 联机曲线没有样本身份

MEAS_EVENT 的字段是 `sequence, mono_us, fresh, classification, quality, ?ohms, ?ratio,
?level, ?interval, lost`（机器定义）。**没有 `sample_index`，没有 `sample_generation`，
没有 `rate`，没有 `recording`。**

后果：

- 联机曲线**无法按样本序号与回放曲线对齐**；
- 联机时不知道当前采样率——必须读 `GET_STATUS.rate`（tag 30）；
  **不能用 HELLO 里的 `rate_monitor`/`rate_record`**，那两处是硬编码常量 4000
  （`drms_cdc_v2.c:674-675`），设备实际可在 1k–64k 之间运行；
- 采集是否重启（代次变化）只能靠 `GET_STATUS.generation`（tag 21）判断。

## 5. 断线与缺口

**核心原则：宁可不画，也不插值。**

| 触发条件 | 界面表现 |
| --- | --- |
| `fresh = 0` | 该点整条曲线断开（主副同时断） |
| `ohms` 字段缺失 | 仅副图断开 |
| `ratio` 字段缺失 | 仅主图断开（常见于未配区间表） |
| `sequence` 跳变或 `lost` 增加 | 在断口处标注缺口，不连线 |
| `GET_STATUS.generation` 变化 | 判为采集重启，**另起一段**，不跨段连线 |
| `classification` 变化 | **不是缺口**，只标注状态切换（见 §6） |

主图与副图的缺口**互相独立**：`ohms` 只需要采集有效，`ratio` 还需要基线与区间表。
会出现"副图有曲线、主图空白"的合法状态，界面要能解释，不能显示成故障。

### 5.1 `lost = 0` 不等于没有缺口

固件的 `lost` **只统计"该发而队列满"的周期**，不覆盖发送侧的丢弃——
`drms_cdc_v2_publish` 先查 `can_send` 再调 `send`，而 `send_v2` 里 `tx_enqueue` 的返回值被丢弃
（`drms_cdc_v2.c:145-176`、`drms_cdc.c:122-128`）。这是已知缺陷（固件 README 未通过项第 3 条）。

**因此**：`lost = 0` 时仍要用 `sequence` 连续性交叉校验。两者任一异常都要报缺口。

### 5.2 质量位要能落到曲线上

`quality`（tag 29）位定义：0=无有效样本，1=帧完整性失败，2=激励无效，3=采样缺口，
4=基线不适用，5=区间表缺失。

界面上缺口的原因应可追到具体位，而不是笼统写"数据缺失"。
位 4/5 尤其重要——它们直接解释主图为空。

## 6. 等级展示

`level`（tag 27）与 `interval`（tag 28）**只在 `classification = CONFIRMED`(=5) 时发布**，
且要求 `fresh`（`drms_application.c:1849-1855`）。

- 等级只能作为"当前状态"显示，**不得由曲线位置反推**；
- `PENDING` 期间只显示"确认中"，不得显示候选等级为当前等级；
- 等级变化应在主图上打时间标记，但**标记的是"确认时刻"**，不是信号真实越界时刻——
  因为 `confirm_us` 会引入确认延迟（`drms_classifier.c:97-104`）；
- 区间色带来自配置的 `intervals`，`h`（回差）使实际切换点与色带边界不完全一致，
  必要时在说明中提一句，不要在图上画两条边界线自相矛盾。

## 7. 时间轴视口与抽稀

### 7.1 核心模型：视口 + 尺度滑块，不是"把全部数据压进一个框"

用户已确认的交互模型：

- **完整数据始终保留**在内存中，不因显示而裁剪或丢弃；
- 横向时间轴是一个**视口**，只显示其中一段；
- 提供**尺度滑块**：拉大 → 看更长时段／更粗粒度，拉小 → 看更细；
- **抽稀比例由视口宽度动态决定**，不是固定值。

同一个文件，视口不同则抽稀比例不同：

| 视口跨度 | 2000 px 宽时每列覆盖 | 绘制方式 |
| --- | --- | --- |
| 1 小时（4 kSPS，1440 万点） | 约 7200 点 | 每列 min/max 包络 |
| 1 分钟 | 约 120 点 | 每列 min/max 包络 |
| 1 秒 | 约 2 点 | 逐点折线 |
| 0.25 秒 | < 1 点 | 逐点折线（样本级） |

### 7.2 联机

100 ms 周期 → 10 Hz → 1 小时 36,000 点。数据量小，可全量保留；
视口模型同样适用（尺度滑块决定显示的时间跨度）。

### 7.3 回放

4 kSPS → 1 小时 14,400,000 点，单文件约 230 MB。**不得整份载入内存**，
必须按 chunk 流式读取（v2 是 chunk 流，天然可顺序解析）。

视口所需的数据可以按需索引：先流式扫一遍建立**分块统计索引**
（每块记录 min/max/首末序号），切换视口时只解码落在窗口内的 chunk。

### 7.4 抽稀必须保尖峰

按像素列取 **min/max 包络**，不得用平均。平均会把瞬态抹平，
而"抓瞬态"正是回放的主要目的（§2.1）。

**包络必须先于界面平滑（§9.1）计算**，或直接对原始值取包络——
否则尖峰会在平滑阶段被吃掉。

放大到每列不足 1 点时切换为逐点折线，此时不再抽稀。

### 7.5 视口操作

| 操作 | 行为 |
| --- | --- |
| 拖动横轴 | 平移视口，抽稀比例不变 |
| 尺度滑块 | 改变视口跨度，抽稀比例随之变化 |
| 滚轮 | 以鼠标位置为锚点缩放 |
| 键盘 | 可选，非必需 |

主副图（§3.5）共享同一视口，平移与缩放必须同步。

**缩放边界**：最细到样本级（每点一像素或更细），最粗到整个文件；
越界时禁止继续缩放，不得静默回弹。


## 8. 联机必须并行轮询 `GET_STATUS`

因为 MEAS_EVENT 缺 4 个关键字段（§4.3），联机界面需要：

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| `rate`（tag 30） | GET_STATUS | 横轴换算、说明当前档位 |
| `generation`（tag 21） | GET_STATUS | 判断采集是否重启（§5） |
| `recording`（tag 17） | GET_STATUS | 是否在记录、能否下载 |
| `fresh`/`quality` | 两处都有，以 GET_STATUS 为准 | 交叉校验 |
| `media_generation`（tag 85） | GET_STATUS | 掉卡/换卡检测 |

建议 1 Hz 轮询。订阅是加速手段，不是唯一数据源——这与交接稿 §5.2
"以 GET_STATUS 轮询为主、订阅为可选加速"一致。

## 9. 界面平滑

### 9.1 已定：做界面级平滑，用通用方式

用户已确认需要平滑。界面平滑是**独立的显示功能**，
不依赖设备侧 `tau_us` 是否生效（后者见 §3.3.1）。

**通用方式（不依赖设备侧 `tau`，不改变数据语义）**：

- 对**显示**做，不改底层数据：原始点全部保留在内存与导出 CSV 中；
- 算法用**居中滑动平均**，窗口可调，**默认约 0.2 s**（联机 100 ms 周期下约 2 点，
  回放 4 kSPS 下约 800 点）；
- **平滑只影响画线，不影响**：等级判定、CSV 导出、任何统计结果；
- 回放模式默认**关闭**平滑（回放的目的是看原始波形），需要时手动打开；
- 联机模式默认**开启**，并在图例标注"显示平滑 N 点（非原始）"。

#### 与"≤0.1 秒"需求的关系（重要）

用户同时确认了"最小可辨变化 ≤0.1 秒"与"需要平滑"，两者在默认参数下**互相冲突**：

- 0.2 s 窗口会把持续 <0.2 s 的变化平均掉，恰好越过 0.1 s 的需求；
- 但联机数据本身只有 10 Hz（§2.1），**0.1 s 已经是数据的地板**，
  平滑只会让它更慢。

**结论**：

1. **平滑窗口默认不得大于 0.2 s**，且必须可在界面上关闭/调小；
2. 需要看 0.1 s 级变化时，**正确做法是关闭平滑并改用回放**，不是在联机曲线上调窗口；
3. 界面必须在平滑开启时明确标注"当前不用于 0.1 s 级判读"。

**禁止**：把平滑后的值写进 CSV、写进任何"分析结论"、或用于 §7.4 的 min/max 包络
（包络必须先于平滑，或直接用原始值，否则尖峰仍会被平滑吃掉）。

**注意**：若固件侧修正了 `tau`（HANDOFF F-1），界面平滑会与设备侧滤波叠加成两级。
届时建议默认**关闭**界面平滑，或把窗口调到明显小于 `tau`。此项不影响当前实现。

### 9.2 待复核

界面平滑默认窗口最终取值需按实板噪声实测后确定（§12 第 4 项）。
若固件 F-1 修正，需重新评估默认是否开启。

## 10. 绘图风格

用户要求**接近 MATLAB 风格**。具体约定：

| 项 | 约定 |
| --- | --- |
| 线型 | 实线细线；主副图同一数据系列用同一颜色，不靠色区分主副 |
| 网格 | 实线浅灰主网格 + 更浅的次网格，开启，不可关闭默认 |
| 坐标框 | 四边全框（box on），刻度朝内 |
| 字体 | 无衬线；字号偏小（MATLAB 默认比例），标签不用彩色 |
| 图例 | 右上或空白角落，无边框或细边框，不遮挡数据 |
| 背景 | 白底，无渐变、无阴影、无圆角卡片 |
| 颜色 | 默认颜色循环取 MATLAB 的蓝/橙/黄/紫/绿；区间色带用低饱和填充+半透明 |
| 刻度 | 工程记数法（`×10³`）而非 SI 前缀，与 MATLAB 默认一致 |
| 标注 | 文字标注用无箭头纯文本，靠近数据点；不用气泡框 |

**不采用**：深色主题（默认）、渐变填充、圆角、投影、图标化图例。

所有曲线共享横轴时必须对齐刻度与网格线，上下两图网格列严格对齐。

## 11. 建立 R₀ 的界面操作

### 11.1 协议侧事实

| 项 | 事实 | 出处 |
| --- | --- | --- |
| 命令 | `BUILD_R0`（opcode 35），请求无字段，成功返回 `operation` | 机器定义 |
| 受理前置 | 采集运行中、**非参考支路**、无校准进行中、基线策略已配置、**当前采样率必须等于基线保存时的采样率** | `drms_application.c:569-572` |
| 策略来源 | `drms_user_config_get_baseline_policy()`，要求 `min_count != 0` | `drms_user_config.c:435-458` |
| 参数 | `baseline_min_count`（tag 81）、`baseline_min_us`（tag 82）、`baseline_max_cv`（tag 83） | 机器定义 |
| 失败条件 | 采集停/速率变化/切到参考支路/丢帧计数增加 → `INCOMPLETE`；超时 → `TIMEOUT` | `drms_application.c:1290-1294` |
| 成功动作 | 停止采集 → 确认静止 → 写入基线 → **重启采集** | `drms_application.c:1310-1320` |
| 结果查询 | `GET_OPERATION`（**`ACCEPTED` 只是受理，不是完成**） | 协议正文 §操作行为 |

`baseline_min_count` 是 CDC 配置的必需字段，会被写入固件的基线策略 TLV（0xD701，
`drms_config_wire.c:113-114`），所以只要配置下发成功，按钮就有可用的策略。

### 11.2 按钮语义

- 位置：联机主界面，与"开始记录/结束记录"同级但**明显区分**；
- 点击后先做本地前置检查（见 §11.3），不通过时**禁用按钮并写明原因**，不发送命令；
- 发送 `BUILD_R0` 后立即显示"建立中"，**收到 `ACCEPTED` 不得显示"已完成"**；
- 用 `GET_OPERATION` 轮询至终态；成功与失败必须给出不同反馈；
- 成功后必须提示"采集已重启"——固件会停止再启动采集（`drms_application.c:1310`、`1320`），
  联机曲线会断一次，`generation` 会变化（§5）；
- 成功后**区间表未配置时主图仍为空**（§3.2），提示语要分开写，不要让用户以为按钮失败。

### 11.3 前置检查项

| 检查 | 依据 |
| --- | --- |
| 采集运行中（`acquisition = MONITOR`=3） | `drms_application.c:569` |
| 不在参考支路（`acquisition ≠ REFERENCE`=4） | 同上 |
| 无维护任务进行（`maintenance = IDLE`） | 同上（`cal_active`） |
| 基线策略已配置（`GET_CONFIG` 可读且 `baseline_min_count ≠ 0`） | `drms_user_config.c:435-458` |
| 当前采样率等于基线保存速率 | `drms_application.c:571` |

注：`GET_CONFIG` 在出厂空配置时返回 `UNSUPPORTED`，此时基线策略必然不可用，
应提示"请先配置基线策略与区间表"，而不是笼统报错。

### 11.4 与参考校准的区别

`CALIBRATE`（opcode 36）是**设备维护**（切 100 kΩ 板内参考标定系数），
`BUILD_R0`（35）是**试件基线**。两者不是同一操作，界面上不得混用同一按钮或同一措辞。
用户交接稿 §4 已点明这一点，此处落实为按钮与文案的分工。
