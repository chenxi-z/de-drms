# 固件整体架构与后续规划

状态：2026-11-06 修订。目标架构与实施约束；不是当前源码完成状态。
规则优先级：闭环契约 C1–C6 > 实施约束 R1–R8 > 前文概述。
任务优先级数值、新增容量、超时与配置区之外的 Flash 新分区尚未定稿，不以本文件代替实现和实板验证。

## 全局约束

- 整体采用上下位机分离；固件内部区分交互前端、业务核心和硬件后端。
- 硬件冻结：不再修改原理图、PCB、器件或接线。现有本机交互为两个按键、五个可控 LED，无显示屏。
- MCU 为 STM32U575RGT6，Flash 1 MiB；不增加显示屏、温度传感器或外部升级存储。
- 脱机可监测和记录；上位机断线不停止本机监测或 TF 记录。
- 模块边界与线程边界分别设计；业务高内聚，通过明确消息和状态契约协作。

## 已确认的使用行为

- 开机自动启动样品测量/监测，但记录默认关闭；启动完成与有效读数之间保留明确的初始化/稳定状态。
- 测量与记录是独立业务：普通监测只更新 RAM 中的结果/统计，不创建测量记录文件，不向 TF 持续写测量数据。
- 只有用户通过本机按键或 CDC 明确请求开始记录，且卡可用、文件创建成功后才进入记录状态。
- 上电、待机唤醒、异常复位、USB 插入/重连、重新插卡均不自动开始或恢复记录。
- 不把“正在记录”作为重启后自动恢复的配置；可以保留参数，不能重放上一次开始动作。
- 基线、配置和校准按明确变更/保存流程写 Flash，监测刷新不触发周期持久化，避免无意义写入。
- 监测计算 R/R0，上升与下降分别判断；阈值、回差及持续确认的具体参数后续定义，不虚构损伤分级标准。
- 无卡仍可监测，不保存测量数据；必须有可用卡才能开始试验记录。
- 记录叠加在监测之上，默认按键开始、再次按键结束；也支持上位机预设定时结束。
- R0 由用户主动建立，按键和上位机均可发起；成功后断电保存，不因开机或记录自动重建。
- 无有效基线时不作正常区间判断；基线建立与仪器参考校准是不同流程。
- 建立基线允许短暂停采以安全保存，监测间断标记无效；保存失败保留原基线。
- 记录故障结束本次记录并报告，监测在数据仍有效时继续；卡恢复后不自动续录。
- 短按、长按先启用，双击能力预留但不启用；开机按住须先释放，长按后不再产生本次单击。

## 客户判定功能

### 客户核心需求：区间映射（暂定结构，未定标）

客户核心需求是将有效测量的 R/R0 映射到可解释的区间，并通过本机 LED 与上位机输出。
六阈值、双向四等级仅作为当前候选，不固定为最终客户规则，不虚构实际阈值或损伤名称。

规划采用有界、可配置的区间表：区间编号、上下边界及端点归属、等级、偏离方向、显示名称和灯光映射。
区间数量与 LED 数量解耦，多个区间可映射到同一等级；首版正常监测的等级输出映射到四灯。
映射算法只输出区间/等级/方向/有效性和所用版本，不直接驱动 LED GPIO。
本机显示模块再按故障、维护流程、短暂提示、正常监测的优先级呈现。

客户规则确定后再定义回差、确认时间及滤波；这些参数会改变瞬态判定，不能擅自当作已确认指标。
配置检查须明确重叠、边界相等、未覆盖区间和未配置时的行为，不能用表项先后顺序消解歧义。
无效/过期测量、无有效基线和未配置映射，均不得冒充正常区间。
记录和上位机结果应关联映射版本及配置快照，以便复现试验判断。
后续验证覆盖每个边界两侧及边界本身、上下方向、跨级、抖动、无效/过期输入和重启恢复。

## 任务与模块边界

| 任务 | 职责 |
| --- | --- |
| 本机交互 | 两按键独立状态机、消抖/长短按、五灯非阻塞效果；独占 LED GPIO |
| 设备控制 | 统一裁决请求，业务独立状态机，预占资源，异步协调，不等待写卡或 USB 发送 |
| 采集 | ADS 与模拟通路唯一控制、启停/换路/稳定、DMA 生命周期和采集故障 |
| 测量处理 | 数据检查、电阻/比值/区间、基线/校准统计、曲线统计与数据分发 |
| 存储 | TF 唯一所有者；FileX、记录、MSC 原始读取及后续协议下载互斥协调 |
| CDC 接收 | 同任务分级接收、拼帧、校验、解码，完整请求提交业务队列 |
| CDC 发送 | 单一发送者；控制结果和关键事件优先，曲线/原始流/下载分块调度 |
| USART1 调试服务 | 独立启动/故障日志及调试指令，不承担正式协议、数据流、文件传输或升级 |
| USB 管理 | 连接/配置/挂起/复位、会话失效，常插调试软断开与重新枚举 |
| 系统服务 | 电池/RTC/诊断快照、配置维护与持久化；普通信息低频刷新 |

USBX 内部线程另行纳入调度与内存预算。看门狗按关键任务实际进展监督，不无条件喂狗。
严重故障可由底层先执行必要安全动作，再上报控制，不等待电脑接收通知。

## 数据、事件与调度

- 数据路径：DMA → 原始帧有界环形缓冲 → 测量处理 → 记录有界环形缓冲 → TF。
- 两级队列为固定生产者/消费者，不增加第三套大型采样缓冲；USB 不能抢读记录队列。
- 坏帧保留原始记录与诊断，不参与有效电阻、基线或正常区间计算。
- 控制走有界消息队列；状态走一致快照和更新标志；短暂提示走有界队列。
- 操作请求、结果、业务事件具有来源、操作编号及业务代次；内部编号与通信请求编号分离。
- 关键故障保留可查询状态，不能仅依赖可能拥塞的通知队列。
- 超时不等于停止；取消必须确认硬件、文件和缓冲不再被使用后才释放资源。
- 迟到结果不能改变新业务状态，但旧操作的资源清理仍须完成。
- 各入口统一裁决；安全停止优先，清除冲突旧请求。普通结束记录不等于全停采集。
- 记录中锁定影响测量解释的配置、基线与校准；修改配置整体校验，版本匹配后一次生效。
- 当前 ThreadX 为 100 Hz，1 tick=10 ms；关键任务由事件唤醒，慢任务周期刷新。
- 批量处理和每轮执行均有预算；持续过载不能靠增加缓冲解决。
- 线程栈、水位、队列和小缓冲统一预算；启动检查资源创建结果，禁止无界运行时分配。

## 通信与 MSC 方向

### 设备唯一身份

USB CDC 的单条连接按点对点会话设计，不引入总线寻址；同一电脑仍可连接多台设备。
设备使用 STM32U575 的出厂 96-bit UID 作为硬件身份，不依赖 COM 编号或可擦除配置。
人读编码规划为 `DRMS-` 加 24 位大写十六进制，按 HAL_GetUIDw0、w1、w2 顺序，
每个字固定 8 位、保留前导零；不截断或仅用 32-bit hash 作为正式唯一标识。
USB 序列号、协议握手和后续新格式记录使用同一硬件身份，Bootloader 与应用保持一致。
当前 USB 序列号仍是固定字符串 DE-DRMS001，动态 UID 序列号尚未实现；已有 v1 文件的
device_id_hash 仍按其既有含义解释，不冒充完整 UID，不静默更改旧文件布局。
可另设用户别名/试件编号，但不能覆盖硬件身份；更换 MCU 会产生新的设备编码。
设备身份、启动标识和连接会话标识分别管理，固件更新和重连不改变设备硬件身份。

正式协议规划为统一二进制帧、可扩展字段和分块数据；旧字段编号/类型/单位不复用或暗改。
握手查询版本和能力，支持控制、曲线、原始流及历史文件下载，按实际带宽协商。
CDC 接收按字节流增量拼帧，不依赖 USB 包边界；发送等待完成后才复用缓冲。
发送最小间隔作为实测待验证的限速参数，不替代完成同步，不写成协议固有要求。
单帧在途不可插入其他帧；在块边界重新调度，主机不读时不得阻塞本机安全处理。

### 已确认的线上定界：COBS + 0x00

正式业务仅通过 CDC；USART1 仅独立调试，不要求实现正式会话或 COBS 协议。
CDC 正式二进制协议采用标准 COBS，不使用 COBS/ZPE 变体，
不再叠加另一套首尾标志与字节转义。线上形式为：

```text
COBS[版本化协议头 + 消息内容 + CRC32] + 0x00
```

原始头、内容和校验字节允许包含零；COBS 编码帧体不含 0x00，末尾零作为帧分隔符。
先对未编码的协议头和消息内容计算 CRC32，再将头、内容和 CRC 一起 COBS 编码。
接收按定界符收集有界帧，完成 COBS 解码、结构/长度检查及 CRC 校验后，才向业务提交请求。
CRC32 的完整参数、覆盖范围和字节顺序将在正式机器协议中明确，不能仅凭“CRC32”互通。

- 解析不依赖 USB 包、发送调用或两次调用间隔；覆盖任意字节位置拆包和一次到达多帧。
- 连续 0x00 作为空帧忽略；坏编码、超长、半帧超时、长度不符及校验失败丢弃并计数。
- 超长后进入丢弃状态直到定界符，不能在坏帧中途重新接纳尾部为完整消息。
- 编码和解码长度均有本机硬上限；长度、队列与流速预算计入 COBS 最坏编码开销。
- 采用有界编码缓冲或分块编码，不为整段原始流/固件包分配编码副本。
- 控制、曲线、原始流、下载及升级数据共用此定界规则，内部消息与数据格式各自版本化。

参考：[COBS 原始论文](https://www.stuartcheshire.org/papers/COBSforToN.pdf)。
这是目标线格式决定；当前 ASCII 调试控制口与 v1 BIN 文件未因此改变，代码尚未接入 COBS。

### USART1 调试边界

USART1 保留为单独调试接口，正常上位机通过 CDC 完成业务，升级也使用 CDC。
调试日志不混入 CDC 二进制帧；生产业务不依赖 UART 连接或日志成功发送。
调试输出低优先级且有界，拥塞允许丢弃并计数，不阻塞采集、控制或存储。
若保留会改变设备状态的调试指令，仍通过统一控制入口和资源互锁，不能绕过安全检查。
正式协议不再承担 USB/UART 两套等价业务会话；主要操作来源是本机按键和 CDC。
当前 UART ASCII 实现继续保留，后续按此职责裁剪，不因本次规划立即改代码。

MSC 使用 CDC + 只读磁盘组合：显式导出，关闭 FileX 并交接后才呈现介质。
导出中监测继续，禁止记录和其他本机文件访问；记录中不导出、不下载。
具体设计及计划见 [MSC 设计](2026-11-05-msc-design.md)、[MSC 计划](2026-11-05-msc-plan.md)。

## 独立配置区规划

以统一持久化服务分别管理用户配置、试件基线和仪器校准，避免业务互相清除数据。
记录包含格式版本、长度、校验和提交标志；新副本有效前保留旧副本，考虑格式迁移。
运行生效与断电保存分别表达；普通修改可合并保存，不按周期反复擦写 Flash。
普通固件升级不得擦除配置；调试工具整片擦除仍会删除配置，须在维护流程中明确。
当前实际仅预留末端 16 KiB 校准区；本节不意味着新配置布局或迁移代码已实现。

### 固定位置：Flash 末端 32 KiB

针对 STM32U575RGT6 的 1 MiB Flash，配置区规划固定为
**`0x080F8000～0x080FFFFF`，共 32 KiB**。页大小按当前官方 CMSIS 定义为 8 KiB，
四页均按擦除边界对齐。沿用当前双 Bank、未交换布局，不通过 Bank swap 改变地址含义。

| 子区 | 起始地址 | 末地址（含） | 容量 | 内容 |
| --- | --- | --- | --- | --- |
| 用户数据 A | `0x080F8000` | `0x080F9FFF` | 8 KiB | 用户配置、R0、阈值等带类型与版本的记录 |
| 用户数据 B | `0x080FA000` | `0x080FBFFF` | 8 KiB | 用户数据的另一提交/整理页 |
| 校准 A | `0x080FC000` | `0x080FDFFF` | 8 KiB | 保留现有校准槽 0 地址 |
| 校准 B | `0x080FE000` | `0x080FFFFF` | 8 KiB | 保留现有校准槽 1 地址 |

用户数据 A/B 是轮换的持久化日志页，不代表两个不同用户；更新和整理时始终保留旧有效数据。
用户配置、基线与阈值逻辑独立，记录格式须保证整理后仍保留全部已提交类型，不能只搬最后一条记录。
基线和影响其解释的配置若需一起更新，使用明确的事务/快照关系，不能在掉电后恢复成不一致组合。
更改或恢复用户配置不得擦除校准 A/B。校准格式若演进，必须识别现有记录后再迁移。
单条记录的格式版本和长度承担扩展能力；不能把持久化格式直接等同于 C struct 内存布局。

**当前与规划的差异：** 现有链接脚本仍允许程序占用前 1008 KiB，只保护后 16 KiB。
写入新增用户数据 A/B 之前，必须先将普通应用可用区域缩至前 992 KiB，并同步生成恢复工具与门禁。
本轮仅确定位置，没有修改链接脚本，也没有写入新增两页。

引入 Bootloader 后，应用、暂存镜像和升级元数据的所有擦写范围都必须在配置区之前结束；
拒绝任何覆盖 `0x080F8000` 及以上地址的普通固件镜像。配置不放 TF，避免无卡时无法脱机监测。

## 后续独立子任务：CDC 固件升级

用户确认先加入规划，本轮不实现升级，不修改链接地址、Option Bytes、启动逻辑或 CubeMX。

采用独立 Bootloader，通过 CDC 分块接收固件包，不通过 MSC 拷贝文件升级。
逻辑分区包含 Bootloader、固定应用、升级暂存、升级状态与独立配置区。
配置区地址按上一节固定；其余区域和 Bootloader 保护方式须按 1 MiB Flash 重新预算，尚未定稿。
不默认启用 Bank swap，不沿用任何未经验证的 A/B 回退承诺。

正常流程：进入维护状态 → 结束记录并释放 MSC → 停采 → CDC 下载至暂存区 →
整包检查 → 提交待安装状态 → 重启 → Bootloader 安装并验证 → 启动应用。

- 使用小型固定缓冲分块写 Flash，不把整包放入 RAM，不直接覆盖运行中的应用。
- 包含目标型号、长度、版本、包标识、块偏移及校验，区分块接受、整包通过与安装成功。
- 识别重复块；恢复下载和安装前验证内容与进度，不能只凭一个标志继续。
- Bootloader 提供最小 CDC 恢复入口，复位早期通过现有按键进入，不依赖主应用健康。
- 升级断电恢复、错误镜像拒绝、配置保护和格式迁移须独立测试。
- 自动回退、镜像真实性验证等策略在该子任务设计时明确，不能把完整性校验当作真实性保证。
- 上位机支持升级前后的 USB 重枚举和连接重建；升级模式不要求运行测量、FileX、MSC。

## 架构复核与接口契约（2026-11-05 补充）

本节完成设计层面的接口、互锁与预算约束；不宣称目标任务已经拆分实现。
整体采用有明确所有者的模块化固件：业务算法不依赖 USB、FileX 或 GPIO；
线程是调度容器，不是模块必须拥有的资源。禁止引入业务之间的同步循环等待。

### 模块接口与依赖

下表是语义接口，不是已存在的 C API；实现时可调整命名，不得改变所有权与完成语义。

| 模块 | 输入 | 输出 | 独占资源与依赖边界 |
| --- | --- | --- | --- |
| 本机交互 | 按键电平、设备/测量快照、瞬时提示 | 标准业务请求 | LED GPIO；不计算区间、不访问文件 |
| CDC 协议适配 | 有界字节流、会话上下文 | 标准业务请求、编码响应 | 协议解析；不直接启动 ADC 或写 Flash |
| 设备控制 | 请求、业务完成事件、故障 | 带操作编号的子任务命令、业务状态 | 业务互锁；不包含滤波、文件编码、灯效算法 |
| 采集 | 启停、采样配置、模拟通路命令 | 原始帧、采集代次、完成/故障 | ADS、SPI DMA、模拟通路；不知道 CDC/记录格式 |
| 测量处理 | 原始帧、不可变配置快照 | 测量结果、区间事件、记录数据 | 算法状态；不调用 LED、FileX、USB API |
| 存储 | 开始/结束记录、数据块、导出/释放/读取 | 文件状态、读取完成、存储故障 | TF 与 FileX 唯一所有者；MSC 回调通过其接口请求 |
| 配置管理 | 候选配置、期望版本、保存请求 | 校验结果、运行/持久化版本 | 规则、迁移、快照；通过持久化后端访问 Flash |
| 持久化后端 | 类型化记录、提交请求 | 已提交/失败、恢复结果 | 配置 Flash 擦写；不判断 LED 或试验业务 |
| USB 管理 | VBUS、USB 栈事件、维护请求 | 会话失效、连接状态 | USB 生命周期；不决定是否开始记录 |
| 系统监测 | 电池、RTC、任务进展 | 带有效期的诊断快照、故障 | 慢速采集；不等待 USB 通知成功才处理危险 |

配置管理、电池、RTC、诊断可以共享慢速任务，但保持独立模块。
Flash 操作通过维护互锁执行，不能使电源故障处理依赖一个被擦写长期阻塞的普通任务。
USART 调试中的状态修改同样进入设备控制，不提供绕过互锁的后门。

### 消息、状态和数据所有权

- 命令公共信封包含来源、内部操作编号、业务代次、目标、载荷类型；CDC 请求另带会话及请求编号。
- 接受请求仅表示已取得执行资格；操作最终结果必须独立报告。拒绝提供稳定错误码与原因。
- 普通队列满立即返回忙；安全停止使用预留通道/锁存请求，重复停止可合并。完成事件必须有预留容量或可查询完成槽，不得静默丢失后永远占用资源。
- 小消息按值复制；大块仅传固定池描述符，明确所有者、长度、代次及归还路径。超时方不能提前复用在途块。
- 快照包含版本、单调时间、有效性与错误来源；读者获得一致副本，不能直接修改模块私有状态。
- 原始环仅采集写、处理读；记录环仅处理写、存储读。USB 使用独立有界小块，不成为任一环的第二消费者。
- 断线清理会话资源；本机试验与会话生命周期分离。旧会话结果不能误投到新会话。

### 状态与资源互锁

使用独立状态轴，避免组合成巨大的单一枚举：采集（初始化/稳定/监测/停止/故障）、
记录（空闲/启动/记录/收尾/失败）、存储所有权（LOCAL/EXPORTING/EXPORTED/RELEASING/QUARANTINED）与介质健康（ABSENT/READY/FAULT）、
维护（空闲/基线/校准/保存/升级）。只有控制模块批准跨轴转换，各资源模块报告实际完成。

| 操作 | 前置条件 | 操作期间约束 | 完成/失败行为 |
| --- | --- | --- | --- |
| 开机监测 | 配置可解释、采集初始化成功 | 稳定前结果无效；记录保持空闲 | 无 R0 仍可输出电阻，不能输出正常等级 |
| 开始记录 | LOCAL、卡可写、采集有效、维护空闲 | 锁定测量配置/R0/校准；不导出或下载 | 文件建立与样本边界确认后才报告记录中；失败不假报成功 |
| 结束记录 | 启动中或记录中 | 停止追加，排空有效尾部、保存最终状态 | 完成后解除锁定；写卡失败报告不完整，监测可继续 |
| MSC 导出 | 记录空闲、无文件下载、维护空闲 | FileX 完全关闭后交接；禁止本机文件访问 | 释放需等待在途块退出后重挂载；失败不同时交给双方 |
| 修改采样/算法配置 | 记录空闲、维护空闲、无存储交接 | 校验后停采、重配、清滤波、进入稳定期 | 硬件失败恢复旧配置；恢复失败进入明确采集故障 |
| 建立 R0 / 仪器校准 | 有效输入、记录空闲、维护空闲、无 MSC/SD 在途冲突（不要求有卡或卡健康） | 独占维护；校准可独占模拟通路；保存前停采 | 新值质量合格且持久化成功才发布；失败保留旧值 |
| 显式保存配置 | 记录空闲、维护空闲、无 MSC/SD 在途冲突（不要求有卡或卡健康） | 进入维护、必要停采；禁止新增冲突业务 | 保存失败保留运行值并标记未保存，不虚报持久化成功 |
| 固件升级 | 按升级流程先结束记录、释放 MSC、停止采集 | 独占维护与升级 Flash；仅提供恢复所需通信 | 按独立升级规格恢复，不自动恢复记录 |
| 安全停止/关机 | 任意状态可请求 | 禁止新启动；先执行必要抑制，再有界收尾 | 超时明确报告未完整保存，不无限等待卡或主机 |

只读状态查询始终可用（实际响应受连接状态限制）。MSC 导出中监测继续；
所有配置修改按C2统一互锁，别名也不例外。
卡异常只终止依赖卡的业务，不把可恢复存储错误自动升级为整机复位。

## 可调参数与版本语义

- 持久化参数：设备实际支持的采样档、连续/定时记录及持续时间、区间表、回差/确认时间、基线采集与质量参数、监测滤波参数、设备别名及试件信息。
- 上位机连接后才能修改这些参数，按键不提供配置菜单；已保存配置用于脱机运行。高级算法参数仍须在验证范围内，不开放任意值。
- 连接参数：订阅类型、曲线刷新、抽取与上传限速；默认不写 Flash，重连重新协商。
- 校时、建立 R0、参考校准、开始记录是操作，不作为重启自动重放的配置。
- 不向普通用户开放任务优先级、队列长度、协议 CRC、安全门限及任意校准系数写入。

配置流程为“读取版本 → 提交完整候选及期望版本 → 整体校验 → 互锁 → 应用 → 返回运行版本”。
保存是独立操作，返回持久化版本；状态同时公开运行版本、持久化版本及未保存标志。
掉电恢复最后有效提交，普通配置恢复默认不清除仪器校准。
采样重配置失败不发布新版本；恢复失败不能继续把旧快照标为有效测量。

时窗优先采用时间单位，转换为样本数时检查上限与舍入并返回实际值。
更改采样率重建滤波/确认状态，增加采集代次并报告无效间隙。
R0/校准绑定其适用条件：未经验证兼容的采样/算法组合将相关值标为不适用，要求重新建立，
不得静默把旧结果当成适用于所有配置。兼容矩阵随实际支持档位共同验收。

## 时间、重试与兼容性

- 定时记录、长按、超时使用单调时钟；RTC 仅标注日期，校时不改变已经开始的持续时间。
- 数据以采集代次、样本序号、实际采样率定位；丢样保留序号缺口，不能压缩时间轴伪装连续。
- 同一会话内状态修改请求按请求编号去重；重复编号且内容相同返回原操作状态，内容不同拒绝。
- 去重缓存有界；过期编号返回过期，不重新执行。会话内编号单调递增、不回绕复用；耗尽后新建会话。
- 重连后先查询设备/操作状态，再决定新请求；不能自动重放未确认的开始、校准或保存命令。
- 正式协议规定未知可选字段可按长度跳过，未知必需字段拒绝；字段编号/类型/单位不可复用。
- 所有长度、字段数量、嵌套深度、帧大小均有硬上限；线格式、文件格式、持久化格式分别版本化，不直接序列化 C struct。
- 新版配置无法解释时保留原始记录并报告不兼容，使用明确安全默认状态；不得自动覆盖未知版本配置。
- 正式协议字段表与机器定义必须成对更新；本节仅定义架构语义，不改变既有 v1 协议。

## 内存与执行预算

以下是源码可核对的容量与目标验收约束，不是实时性能承诺。

| 项 | 当前容量 | 设计处理 |
| --- | --- | --- |
| 原始环 | 4096 帧；按当前 16 B/帧为 64 KiB | 保持单生产者/单消费者 |
| 记录环 | 32768 帧；按当前 16 B/帧为 512 KiB | 不复制为 USB 大环 |
| 写卡 staging | 32768 B = 32 KiB | 唯一存储线程管理 |
| 三者合计 | 608 KiB | 不含线程栈、中间件、DMA、快照及协议缓冲 |
| 主 RAM 链接区域 | 768 KiB | 上述三项后仅剩 160 KiB 容纳全部其他资源，不能视为可自由新增空间 |
| SRAM4 链接区域 | 16 KiB | 未分配前不计入可用预算，使用时另核 DMA/掉电属性 |

实现阶段必须从 ELF/map 生成不重复计数的清单：静态区、各池及其内部栈/缓冲、主栈、对齐、
剩余空间；池内栈不能再作为额外占用叠加。每个新增线程与队列有明确预算，启动分配失败立即暴露。
首版不运行无界堆分配；压力测试检查栈水位、池余量、队列峰值与丢弃计数。
具体线程栈大小与队列深度由调用链和实测确定，在取得证据前不编造定值。

缓冲时间上限（从空环算起，不包含抖动余量）：

| 采样率 | 原始环 | 记录环 | 16 B/帧数据率，不含文件开销 |
| --- | --- | --- | --- |
| 4 kSPS | 1.024 s | 8.192 s | 64,000 B/s |
| 128 kSPS | 32 ms | 256 ms | 2,048,000 B/s |

实际容忍停顿为“剩余空槽 / 采样率”。平均吞吐足够也不代表卡的最长停顿可接受。
支持档位按采集、记录、上传组合公布，未通过压力测试的组合不可作为正式支持能力。

| 调度路径 | 执行约束与验收 |
| --- | --- |
| ISR/DMA | 仅搬运、发布和必要安全动作；按采样周期验证最长屏蔽/服务时间，不依赖 10 ms tick 满足采样时序 |
| 采集与处理 | 事件唤醒，分批且限制每批执行；最坏积压不越过原始环剩余时限 |
| 控制 | 高响应、短执行，不同步等待存储/USB；停止请求在负载下测端到端最大延迟 |
| 存储 | 测持续吞吐及最长写停顿；超过预算明确结束记录并标记缺失 |
| CDC TX/RX | 单次帧/块有界；不读主机、坏帧洪泛不能耗尽控制资源或饿死采集 |
| 本机交互 | 目标约 10 ms 刷新，动画不阻塞；按键响应按消抖/调度共同验收 |
| 系统诊断 | 普通信息目标约 1 s 更新；危险条件独立事件上报，不等待普通刷新/USB |

优先级数值在实现前结合 ThreadX/USBX 内部线程统一确定；不能照搬 FreeRTOS 中断门限。
需要的板测证据为最大延迟/停顿、吞吐、水位、溢出及恢复结果，不只报告平均 CPU 占用。

## 设计验收与实施拆分

1. 纯逻辑验证：区间边界、滤波与无效输入、按键状态机、配置整体校验/迁移、协议任意拆包。
2. 生命周期验证：取消后迟到完成、队列满、重复请求、断线重连、RTC 跳变、配置应用失败与保存掉电。
3. 存储互锁验证：记录/导出竞争、拔卡、写满、在途 MSC 读取取消与重挂载；绝不双重拥有介质。
4. 负载验证：各采样档结合记录/上传/LED 动画/慢主机，记录最坏延迟与水位；失效有明确降级。
5. 边界检查：算法模块不包含 USB/FileX/GPIO 头；交互模块不直接写采集/Flash；业务修改走统一入口。

先实施已有独立规格的 MSC 生命周期；再拆任务与所有权、配置/R0/区间、正式 CDC 协议与记录格式。
每部分单独形成可审查实施计划；升级保持后续独立子任务，不塞进本轮任务重构。
本文为待用户复核的目标架构规格；具体协议字节布局、线程容量/优先级与升级分区在各子任务计划中闭合后实施。


## 实施约束 R1–R8（2026-11-06 复核修订）

本节规定实现者不得自行放宽的结果条件；配套执行计划为
[架构收敛实施计划](2026-11-06-firmware-architecture-plan.md)。
不要求在本轮实现 Bootloader、完整新协议或客户尚未给出的阈值。

### R1 记录边界、顺序和文件完成

- 开始请求先预占记录资源，状态为 STARTING。存储线程建立文件并写入配置快照成功后发 READY。
- 处理线程收到 READY 后，在处理循环边界确定首样本：按C1一致边界确定起点，不回录开文件期间积压的旧样本。用户看到 RECORDING 后才代表采样记录已开始。
- 按键时间是请求时间，实际首样本边界另行报告；不承诺从按键电气边沿开始无损记录，不隐式添加预触发功能。
- 普通停止由处理线程请求采集模块按C1捕获一致的排他末边界；处理并记录边界前尚未处理的数据，边界后仍监测但不加入本次记录。
- 使用内部单调 64-bit 流位置定位边界，使用采集代次区分重启；不能仅用会回绕的 32-bit 原始序号比较大小。小于 64-bit 原始序号的扩展由唯一生产端管理。
- 记录环不重置在途数据。处理线程停止追加本次数据后，以 release 发布 END 描述符（record_id、generation、末环水位、首末样本、损失统计和原因）；存储以 acquire 获取，并消费到该环水位后收尾。
- END 使用每次记录独占的完成槽，不占可能已满的数据环；槽在存储确认之前不能被下一次记录覆盖。数据发布和 END 发布顺序必须有内存序保证。
- STARTING 时取消：尚未开放数据入口则关闭已创建文件并报告 CANCELLED；不得迟到转为 RECORDING。
- 数据环满时不无限等待：停止追加、发布损失计数与失败 END；已入环数据可以排空，最终结果为 INCOMPLETE。
- 文件最终成功条件：不存在采集/队列丢失，边界内已接收的数据写入、尾信息写入、文件关闭和介质 flush 均成功。此为文件系统 API 成功语义，不承诺拔电时卡内部缓存绝不丢失。
- 拔卡/写满时可能无法写入尾信息：运行状态报告 INCOMPLETE；后续解码把缺尾/CRC 错误识别为不完整，不能伪造成功尾。
- 安全停止优先停止硬件，不为精确边界延迟安全动作；以最后可确认数据边界收尾并明确原因/缺口。

### R2 资源预占与状态裁决

控制模块唯一串行处理业务请求，检查前置条件、分配 operation_id、预占资源和进入过渡状态是同一步。
中间不等待、不回调外部模块；只有完成预占后才投递异步工作。
资源为 ACQUISITION_CONFIG、RECORD_SESSION、TF_ACCESS、FLASH_MAINTENANCE、UPDATE_EXCLUSIVE。
资源申请使用一次性全量检查，不逐项持锁等待；失败不留下部分预占。
工作队列满须回滚尚未启动的预占并拒绝；命令已送出则必须走取消确认后释放。

- 开始记录预占 RECORD_SESSION、TF_ACCESS，并锁定采集配置与解释快照。
- MSC 导出预占 TF_ACCESS，覆盖全部交接和导出阶段。
- R0/校准/配置保存预占相应维护资源；Flash 保存前确认采集停止、DMA 退出。
- 安全停止增加控制代次、锁存 STOPPING 并拒绝所有新启动；旧完成只允许清理，不能启动业务。
- 只有全部必要清理完成才解除 STOPPING；隔离资源存在时保留对应功能不可用状态。
- 隔离/故障状态不能因读取 STATUS、USB 重连或普通清错命令变为可用。

### R3 配置与 R0 的原子持久化

用户区以一个版本化快照提交配置、R0 和 R0 依赖标识；不要以各自独立提交标志拼装最新值。
快照包含 schema、提交序号、长度、CRC、配置版本、R0 有效性、R0 的采集/算法/校准依赖标识。
建立 R0 时冻结运行配置；质量通过后，将该配置与新 R0 一起提交，成功才整体发布。
因此建立 R0 成功会同时保存其依赖的运行配置，上位机必须显示此语义；失败保留旧 R0，运行配置仍可保持未保存状态。

- 校准区继续独立 A/B。新校准提交后，旧 R0 只有依赖匹配才有效；若更新 R0 失效标记前掉电，启动依赖检查仍必须使其无效。
- 不因旧 R0 失效而删除旧值，可用于诊断；不得用于正常区间判断。
- 用户快照最大编码长度 4096 B（包括头、CRC、提交字段），区间最多 16 项，名称每项最多 48 UTF-8 字节；超限拒绝，禁止截断。
- 两页各 8 KiB：写新页之前保持旧有效页；擦除目标→写内容→校验读回→最后写提交标志→校验提交→允许以后回收旧页。
- 不依赖 C struct 布局；擦写单位、提交粒度和掉电状态按芯片后端核对后实现。任何中间掉电恢复得到完整旧快照或完整新快照。
- 同值显式保存可返回 NO_CHANGE，不擦写；不设周期保存。
- 未知未来 schema 保留且进入配置恢复状态；普通保存不得覆盖，只有用户明确恢复默认才允许重建用户区，校准区不动。
- 写新增两页前必须缩减链接区域至 992 KiB 并同步生成恢复工具；否则拒绝启用用户区写入。

### R4 取消、隔离和恢复

资源操作生命周期：IDLE → ACTIVE → CANCELLING → QUIESCENT，失败不能确认静止则进入 QUARANTINED。
QUIESCENT 的证据是外设传输停止、相关 IRQ/回调不能再使用旧缓冲、所有者不再访问旧请求，不能以软件 busy=0 代替。
取消超时后：保持缓冲占用→一次有界中止/外设恢复尝试→确认静止后归还；仍失败则隔离并保留固定槽。
隔离不再接收新工作，因此不能持续泄漏更多缓冲。迟到回调核对代次并仅清理旧请求。

每个硬件后端必须提供 timeout/abort/recover 的显式结果；超时值取已验证驱动边界，未确定就不能通过该后端实施门禁。
不在这里给未经数据手册/实测验证的毫秒常数。测试使用注入时钟与可配置小超时，不等待真实秒数。
SD 隔离允许纯监测继续；采集隔离使测量无效；仅在无法隔离且有内存/执行安全风险时允许系统复位。
看门狗区分“活动任务应有进展”和“已报告隔离的静止资源”，不能因为隔离状态无限重启。
关机到达总收尾期限后，不再承诺文件完整；若仍有 DMA 无法确认停止，禁止带着在途访问直接重用内存或进入不安全的低功耗转换，升级到受控复位路径。

### R5 介质所有权与健康分离

所有权为 LOCAL/EXPORTING/EXPORTED/RELEASING/QUARANTINED；健康为 ABSENT/READY/FAULT。
无卡是 LOCAL+ABSENT，挂载失败可以为 LOCAL+FAULT；只有硬件/在途请求无法安全释放才是 QUARANTINED。
LOCAL 不意味着文件系统已挂载；开始记录额外要求 READY 和成功挂载。
R0/Flash 保存不要求 READY，只要求不存在与维护冲突的在途资源。
SD 已确认静止的故障不阻止内部 Flash 保存；SD 未静止的隔离默认拒绝维护，先完成恢复。
外部旧 MSC ERROR 可作为兼容显示值，由所有权/健康/最近错误投影得到，不作为内部所有权。
MSC 原设计中 ERROR 的解释按本节修正，其他只读和介质交接条件继续有效。

### R6 两类实时期限与预算门禁

硬件捕获期限独立于软件队列积压期限：DRDY→SPI 开始→完成必须满足 ADC 下一数据覆盖约束；
原始环只能缓冲已经捕获的帧。128 kSPS 周期为 7.8125 µs，不由 10 ms tick 调度逐帧读取。
流位置应覆盖所有观察到的 DRDY（包括未成功读出的帧），不能只为成功DMA递增；无法确知丢失数量时记录 LOSS_UNKNOWN 并使试验不完整。
ISR 与采集线程属于同一模块所有权；ISR 可在该模块内启动逐帧 DMA，不经业务线程逐帧往返命令。
处理算法按批次执行，但持续就绪的高优先级线程不能靠普通 yield 保证低优先级线程运行。

- 正常数据线程优先级/时间片必须让处理与存储在持续负载下都获得运行机会；控制消息限制每轮数量，安全停止走独立锁存入口。
- 实现阶段先列出全部应用及 USBX/FileX 线程，再选择具体优先级；逐项记录阻塞点、最长执行段和持有的锁。
- 不在持锁状态同步等待 USB/SD 完成；需要互斥锁时限定临界区并检查优先级反转。
- 不把高采样率下固定 sleep(1) 当公平性修复；任何休眠/批次策略都须计入剩余环水位时限。
- RAM 门禁：map 中主 RAM 全部静态、池、主栈/堆及对齐预算总量≤736 KiB，保留至少32 KiB未分配余量；已有池内对象不重复计数。
- 动态水位门禁：每个栈实测余量≥max(256 B, 分配的25%)；不足则调整预算再测试，不降低门槛。
- 未通过板测的高速组合保持实验性能力，不向正式能力列表宣称支持。缺硬件时只能完成软件验收，不能宣布实时验收通过。

### R7 测量处理模块内部边界

在同一处理线程内依次执行：decode/quality → resistance/calibration → filter → classify → distribute。
基线/参考校准统计读取合格样本，但不直接写 Flash；完成候选由控制模块协调提交。
保留现有 drms_measurement 的解码/换算纯函数；新增 filter、classifier、baseline 模块各自拥有显式状态。
分发层唯一决定哪些样本进入记录/上传，算法模块不认识文件、LED、USB、RTOS 句柄。
原始记录保留坏帧及质量信息，不因滤波或分类失败删去采样证据；不制造插值帧冒充原始数据。
算法逐样本流式计算，不引入与采样率×任意时窗成比例的无界缓存。

### R8 无效输入与恢复

每份结果包含 valid、reason、sample_position、generation、config_version、baseline_version。
CRC/格式/ADC故障、非法分母、非有限数、采样缺口、过期、配置切换或依赖不适用均不能参与正常等级确认。
无效输入立即取消正在进行的等级持续确认，清除滤波有效状态；历史结果仅作带时间戳的诊断。
恢复后要求连续合格样本覆盖完整滤波建立窗口，再从零累计等级确认时间；无效时段不能计入确认时间。
LED 显示无效/故障状态，不能维持绿色正常外观；上位机可以同时显示灰色历史值与当前无效原因。
首版区间等级不锁存；故障诊断可锁存，但与区间等级分开。将来客户要求严重等级锁存须新增明确可配置语义，不暗改旧算法。
未提供区间表时 status=UNCONFIGURED，不填造客户阈值；跨越多个区间直接按候选目标区间确认，不强制逐级停留。
恢复策略和滤波参数进入记录快照；纯逻辑测试必须覆盖有效→无效→恢复及跨代次事件。


### 本次纯算法实现选择的适用范围

配套计划采用一阶IIR作为首版监测滤波，旁路可选；它不改变原始记录数据，也不代表客户已认可其动态响应。
alpha = 1 - exp(-dt/tau)，tau=0旁路；恢复有效窗口与区间确认时间独立，不能合并计时。
R0 使用有效电阻样本的流式均值/方差评估，数量、时长与稳定限值由已验证配置提供；无合格参数时返回UNCONFIGURED。
区间退出回差不改变表的物理端点：已确认区间可在其边界外保持配置回差宽度；超过后按原表寻找目标候选并重新确认。
无效结果优先于回差保持；时间和版本变更均重置状态。上述算法先以合成配置验证，客户阈值与默认时间参数仍需定标。

## 闭环契约 C1–C6（2026-11-06，优先于前文歧义表述）

本节是二次复检后的执行依据。方案闭环不等于代码/实板验收完成；每项有对应测试和失败结果。

### C1 三种位置与一致边界

- `sample_seq`：采集模块为每个观察到的DRDY分配的64-bit序号，丢弃的采样也占序号。
- `raw_ticket`：原始环成功发布帧的64-bit累计数量；失败入环不递增。
- `log_ticket`：记录环成功发布帧的64-bit累计数量；不得与前两者比较大小。
- 三者都表示“下一个位置”时使用 `_next` 后缀；区间统一采用 `[first,end_exclusive)`。
- `DRMS_CaptureBoundary`：`uint32_t acquisition_generation; uint64_t sample_next, raw_next;`。

边界由采集模块串行执行请求：等待当前DMA完成/确认中止，将边界前观察到的DRDY归结为已发布帧或明确损失，
再在短临界区捕获sample_next/raw_next。等待发生在临界区之外，不屏蔽中断等DMA。
边界准备期间无法捕获的DRDY计为损失；不能声称边界无扰动。不能在捕获时混入尚未归结的旧DMA。
超时按R4失败/隔离，不生成伪完整边界。

开始：文件READY→请求一致边界B→处理线程跳过raw_ticket<B.raw_next的积压→接收之后的数据。
首采样边界为B.sample_next；确实收到第一帧后才发布RECORDING，此前仍为STARTING。
停止：捕获边界E→处理至raw_ticket==E.raw_next→发布END，文件样本范围为[B.sample_next,E.sample_next)。
E之后捕获的帧只用于监测。END的ring_end是独立log_ticket，不是E.raw_next。
开始后首帧前停止得到合法空区间，结果EMPTY（无正常试验记录）；STARTING取消不等待首帧。
已发生的确定/未知损失使最终结果INCOMPLETE；无法数出全部物理DRDY时标记LOSS_UNKNOWN，不伪造精确序号。

不扩大512KiB记录环中的16B帧：保持低32-bit序号，完整64-bit起始锚点放在会话描述符。
处理端按顺序扩展，任何连续可证明跨度须小于2^31个采样；违反时停止本次记录并标记LOSS_UNKNOWN。
世代切换前先排空或明确废弃旧环，不能混代复用。环ticket内部也以64-bit快照处理，不假设单条64-bit写原子。

**验收C1：** 合成DRDY100..109，其中102未读出，raw_ticket只增加9；记录边界仍为[100,110)，
结果INCOMPLETE且缺口102明确。另测在途DMA、入环失败、低32位回绕、空记录、连续两次试验、取消后迟到边界。

### C2 确定的操作资源集合

所有资源都是独占租约；下表替代“相应资源”等不确定描述。普通监测不持有配置租约。

| 操作 | 必须一次性申请的资源 |
| --- | --- |
| 记录（含STARTING/收尾） | ACQUISITION_CONFIG + RECORD_SESSION + TF_ACCESS |
| MSC导出（含全部交接） | TF_ACCESS |
| 文件下载 | TF_ACCESS |
| 修改采样/算法配置 | ACQUISITION_CONFIG + FLASH_MAINTENANCE |
| 建立R0、仪器校准、用户配置保存 | ACQUISITION_CONFIG + TF_ACCESS + FLASH_MAINTENANCE |
| 升级 | 全部五项资源 |

申请集合与已占集合相交则BUSY；UPDATE_EXCLUSIVE申请必须扩展为全部资源，禁止单独申请该位。
TF_ACCESS租约在Flash维护中仅用于阻止SD交接/新I/O，不要求有卡、挂载或卡健康。
所有配置修改（包括别名）首版统一通过配置操作，记录期间拒绝；删除前文“记录中可改别名”的例外，避免版本快照漂移。
停止/取消是现有租约操作，不重新申请与自身冲突的资源；查询不申请租约。安全停止使旧启动失效，但不凭代次变化释放物理资源。

**验收C2：** 遍历上述7类操作的全部有序组合，按集合相交判定唯一预期；再覆盖STOPPING、队列投递失败回滚和隔离未释放。

### C3 无样本也必须超时失效

处理任务除数据唤醒外，必须有独立定时唤醒，每10ms至少检查一次测量新鲜度。
`stale_timeout_us` 是配置中的正整数微秒，最低10000；采样档验收同时给出适用范围。
这只限制显示/业务新鲜度，不代替ADC硬件捕获期限。
当前样本采集时间与检查时刻使用同一单调时间域；不以“处理时刻”刷新旧积压样本的新鲜度。

当now_us-last_valid_capture_us >= stale_timeout_us时立即发布STALE，清滤波和候选确认。
无样本超时的可见失效上界为stale_timeout_us + 10ms + 实测最大调度延迟；调度延迟在T7/T8记录，不能省略。
系统无第一帧时保持INITIALIZING/INVALID；RTC校时无影响。停止、换代立即失效，无需等超时。

**验收C3：** 最后有效帧时间100000us、超时20000us：119999有效，120000失效；不调用样本step只调用tick亦成立。
再测旧帧积压、时间回绕适配、换代和失效后恢复窗口。时间倒退视为时基故障，不作无符号差值误判。

### C4 文件格式是记录交付前置条件

T2拆为T2a“内存边界协议”和T2b“新版文件格式”。T2a只允许报告边界单元测试通过，不能宣布记录交付。
T2b须先完成可审查字节规格与黄金文件再实现编码/解码：字段偏移/长度/端序、CRC全部参数和覆盖范围、
头的配置快照及UID、数据chunk、实际首末边界、确定/未知损失、END状态、空记录、截断处理都必须固定。
BIN v1只读兼容，新的写入版本不得覆盖旧解释。配置快照使用T5冻结的编码，因此T2b在T5之后执行。
没有T2b不得进入T7系统集成；T2b遇到未定义字段不得自行发明并直接声称验收通过。
这属于执行中明确的规格交付门禁，不需要再次询问已确认的功能需求。

**验收C4：** 同一黄金文件由固件编码与主机独立解码校验；逐字节截断/位翻转、坏长度、缺END均不被认作完整记录。
一个成功文件必须能恢复配置、完整采样边界和损失状态；无卡/写失败结果可只存在运行诊断，不能伪造落盘成功。

### C5 公共接口完成门禁

接口须先写头文件契约再写实现。新增 `Core/Inc/drms_architecture_contract.h` 作为规划中公共类型的唯一位置；
原计划drms_contract.h命名统一改为此名。头文件仅包含标准C类型，不包含HAL/RTOS；其他模块只引用它，不复制类型。

控制/记录/资源模块各提供`init`、一致`get_snapshot`；控制提供`submit`/`poll`，资源生命周期提供`tick`。
submit只复制命令并返回ACCEPTED/BUSY/INVALID；最终结果走带token的completion，不以submit返回OK冒充完成。
控制、采集和记录代次为不同命名字段，禁止一个generation同时表示三个生命周期。
完成槽必须保留操作编号、完成结果和已确认静止掩码；控制任务消费，普通通信查询不能清空它。

T1开始先交付公共头文件，编译头文件自包含测试，并建立类型、单位和上下文清单；此门禁失败不得开始后续模块。
C6给出的算法公共契约也在此阶段冻结，T6实现不得改变字段语义。

### C6 区间、回差与输出状态

首版每项区间为有限边界[lo,hi)，lo<hi；最后一项允许闭合上端。内部交界只归右侧，禁止零宽、重叠或两侧同闭。
允许空隙，空隙为UNMAPPED；不允许NaN/Inf边界。
每项退出回差h>=0且2h<hi-lo；相邻有空隙时额外要求两侧h之和严格小于间隙，防止把整个空隙吞没。
查表得到observed，再处理已确认区间的扩展保持范围[lo-h,hi+h]（h=0时严格使用原区间端点）。

| 输入/条件 | observed | candidate / confirmed | 当前显示状态 |
| --- | --- | --- | --- |
| 无效/过期/版本变化 | 无 | 两者清空 | INVALID，历史值另存 |
| 滤波尚未建立 | 原始值仅诊断 | 两者清空 | WARMUP |
| 未配置表 | 无 | 两者清空 | UNCONFIGURED |
| 有confirmed且仍在其保持范围 | 按原表计算，可不同 | 清candidate，保留confirmed | CONFIRMED，明确回差保持标志 |
| 不在保持范围且observed为空隙 | 无 | 两者清空 | UNMAPPED |
| 不在保持范围且observed有值 | 目标区间 | 旧confirmed转历史；设置/延续目标candidate | PENDING，不显示旧正常等级 |
| candidate连续达到确认时长 | 目标区间 | candidate转confirmed并清candidate | CONFIRMED |

candidate变化即从当前样本重新计时；返回历史区间也重新确认；确认时间0当帧确认。
确认以连续有效样本的采集时间计算，不能按处理批次耗时计算；没有新样本不能凭tick完成确认。
优先级为INVALID/WARMUP/UNCONFIGURED，其次回差保持/查表；UNMAPPED不冒充正常。
PENDING时本机显示独立待确认效果；五灯具体动画由交互规格定义，禁止以常亮正常灯表达待确认。

算法公共类型固定为：
- Input：ohms（double）、capture_us（uint64）、sample_seq（uint64）、acquisition_generation（uint32）、quality_flags（uint32）、config_version/baseline_version（uint64）。
- Config：rate_hz（uint32）、tau_us/warmup_us/confirm_us/stale_timeout_us（uint64）、r0（double）、baseline_valid（bool）、interval_count（uint8）、intervals[16]。
- Interval：lo/hi/h（double）、id（uint16）、level（uint8）、last_upper_closed（bool）；显示名称保留在配置编码中，不进入算法热路径。
- Output：state（INVALID/WARMUP/UNCONFIGURED/UNMAPPED/PENDING/CONFIRMED）、reason（位集合）、observed/candidate/confirmed（int16，-1无）、ratio（double）、hysteresis_hold（bool）、输入对应的位置/版本字段。
- Context：仅由算法持有，init后不共享可写；具体内部滤波/统计字段可变，调用方不得直接读取。

统一函数：`void drms_monitor_init(DRMS_MonitorContext *ctx);`
`DRMS_Result drms_monitor_configure(DRMS_MonitorContext *ctx, const DRMS_MonitorConfig *cfg);`
`void drms_monitor_step(DRMS_MonitorContext *ctx, const DRMS_MonitorInput *in, DRMS_MonitorOutput *out);`
`void drms_monitor_tick(DRMS_MonitorContext *ctx, uint64_t now_us, DRMS_MonitorOutput *out);`
configure复制已验证配置，失败保持旧配置；step/tick由处理线程唯一调用。滤波、分类和基线内部函数不作为跨线程公共接口。

**验收C6：** 表驱动覆盖每一行、所有端点、h=0、空隙、跨级、候选反复变化、无样本tick、同样输入不同分批方式。
同序列和同配置应得相同输出，不受USB/文件/线程调度改变处理批次的影响。

### 预算来源与放行条件

736KiB RAM上限、32KiB预留、栈余量max(256B,25%)是本项目提出的工程门禁，不是芯片规定或实测结果。
门禁可通过重新分配缓冲满足，不可通过改变统计口径绕过。实际栈大小/超时/调度延迟必须留下证据。
C1–C6对应故障用例全部通过且公共接口/文件格式已冻结，才允许标记“软件架构收敛完成”。
板测未执行仍只能声明软件完成；客户阈值未定时保持UNCONFIGURED，不阻塞纯算法合成测试，不宣称客户功能已定标。
