# 上位机需求讨论与开发交接

日期：2026-11-13。接续对象：zcode + DeepSeek。

本文整理用户与 Codex 已进行的需求讨论，供接续设计与开发使用。它是需求交接稿，不是已经审批完成的详细设计或实施计划；尚未选定技术栈、界面方案、具体性能参数，也未开始上位机实现。不要把下文建议自动升级为用户确认。

## 1. 用户已经确认的方向

| 项目 | 已确认内容 |
| --- | --- |
| 产品定位 | 完整的仪器软件：现场操作、试件与试验管理、历史数据分析、设备配置维护 |
| 使用者 | 要交付给其他人员共同使用，不能仅按开发者自用工具设计 |
| 运行方式 | 本地独立软件，各人自行保存数据；不需要服务器 |
| 平台 | 排除 macOS；Windows 是主要交付平台，Linux 使用少；当前开发环境为 Ubuntu 24.04 |
| 平台讨论结论 | 用户接受 Windows 为主、Ubuntu 开发、保留 Linux 使用能力的方向；具体框架与打包路线未选。Wine 只是讨论过的选项，不是已确定依赖 |
| 连接规模 | 首版一台电脑连接一台仪器，为未来兼容升级保留空间 |
| 试验方式 | 联机观察与控制、设备独立记录后再连接电脑取数，两种都需要 |
| 历史数据范围 | 首版处理本设备数据；暂不要求导入其他仪器的 CSV、Excel 数据 |
| 数据导出 | 原始 BIN 和解析后的 CSV 都需要保留/导出；软件应能识别并重新打开本设备历史记录 |
| 实时内容 | R、R/R₀、两者的时间曲线、当前数值、记录状态与有效的分级结果都需要 |
| 开发顺序 | 慢测试优先，慢测试通过后再推进快测试；最终兼顾两类试验 |

“多人使用”指软件交付给多位使用者，不代表多人共享服务器、集中账户或在线协作。

## 2. 接续时从哪里继续讨论

上一个尚未得到回答的问题：**一次慢测试通常持续多久，最小需要看清多快的变化？**

例如持续半小时、希望看清 0.1 秒变化，或连续几天、每秒更新即可。不要自行选择其中一种当成用户需求。

接下来还需逐步明确：

1. 慢测试典型/最长时长、变化时间尺度、记录需求与验收方法。
2. 采样率、记录率、传输/曲线点率、界面刷新率分别如何设置；不能把它们当作同一参数。
3. 试件管理深度、必填信息、操作人是否仅为备注字段。未提出登录或权限系统。
4. 试验是否需要定时结束、人工事件标记，以及结束后的自动下载选项。
5. 历史分析首版范围、多次曲线对比、图片导出与报告需求。
6. 基线建立流程、稳定判据及等级阈值的实测来源；不得臆造数值。
7. Windows 版本、目标电脑配置、安装包与升级方式。
8. 是否有 Windows 实机用于交付验收；Ubuntu 正常或 Wine 正常不等于 Windows USB 验收通过。
9. 技术栈、界面风格、数据存储方案和模块边界。

一次聚焦一个关键问题；已有确认不要重复询问。用户本次要求先整理文档、移交其他 agent，没有授权跳过后续设计讨论直接生成全部产品。

## 3. 建议的首版工作流（待细化确认）

### 3.1 联机试验

连接设备并握手 → 查询当前状态与已有记录 → 选择/填写试件信息 → 检查测量、基线、配置与卡状态 → 用户明确发起记录 → 实时观察 → 用户结束或设备按配置结束 → 查询最终结果 → 下载 BIN → 查看历史曲线并导出 CSV。

中途接上正在记录的设备时先观察、识别已有记录；不能隐式启动、结束或接管。拔掉电脑后本机记录继续。

### 3.2 离线试验

设备独立记录 → 之后连接电脑查询并下载，或从 TF 卡取得 BIN → 校验和解析 → 补充试件名称/操作人/备注 → 本地归档 → 分析和导出。

设备不一定具有电脑端填写的全部信息。电脑补填信息应绑定原始设备记录，不能假称这些信息原本就在 BIN 中。

### 3.3 本地保存与交换

建议原始 BIN 原样保存，试验信息与分析设置另行关联；支持重复导入识别和整场试验打包，以便同事或另一台电脑重新打开。CSV 全量/选区导出、图片导出、整体打包是建议，具体方式仍待确认。

导出 CSV 的列、时间基准、单位、精度、无效值与缺口表达需形成规格。不得用界面抽点或平滑结果冒充完整原始记录。大文件应流式解析/导出，避免全部载入内存。

## 4. 已提出但用户尚未逐项确认的功能建议

| 方面 | 建议 |
| --- | --- |
| 试验信息 | 试件编号、试验名称、操作人、备注；同一试件关联多次试验 |
| 试验前检查 | 设备连接、测量有效、基线、阈值、卡可写状态；剩余容量仅在固件实际提供时显示 |
| 实时显示 | ΔR/R₀ 百分比、基线值、数据新鲜度、记录时长；不把旧等级维持为当前正常状态 |
| 曲线 | 缩放、平移、自动跟随、暂停画面、游标读值；不同量的时间轴联动 |
| 结果 | 文件关闭完整性与采样损失分别显示 |
| 历史管理 | 按试件/时间/设备检索、重复识别、原记录身份追溯 |
| 分析 | 区间统计、最大/最小/均值、变化幅度、多次试验叠加 |
| 维护 | 身份/固件版本、校时、参考校准、配置读取与保存 |
| 异常 | 重连状态恢复、下载重试、掉卡/缺口提示、可导出诊断信息 |

参考校准与试件 R₀ 是不同操作。建议保存试验当时的基线和参数；事后用新基线分析时保留原始依据。界面暂停不能被误解为停止采集或记录。

正式报告、复杂算法、USB 固件升级和多设备并行是后续候选，不作为已确认首版范围。多设备扩展不代表承诺跨设备同步采样。

### 5.2 已有接入能力及限制

- CDC v2 已提供握手、状态/操作/记录查询、启停记录、配置、基线、参考校准、校时、文件列表及下载、MSC 导出/交还、安全停止和恢复监测。
- CURVE 周期订阅已接通，较早聊天中“实时推送尚未接通”的描述已过期。100/200/500/1000 ms 周期已有有限实测；按协商返回周期运行并保留状态轮询恢复能力。
- RAW 原始流订阅当前不可用；不能承诺 USB 实时传输全量原始采样。
- OP_EVENT、FAULT_EVENT 等完整异步事件路径仍未完成；操作受理后要用 GET_OPERATION/GET_RECORD 查询结论。
- 128 kSPS 当前不可用且被入口拒绝。64 kSPS 采集及约 68.65 秒短时记录有通过记录，但后续长时测试出现 log_drop；不得承诺长期无损记录。
- 固件说明同一段对长时失败存在“约 10 分钟”和约 298 秒的文字差异，应核查原始测试记录，不据此设定保证时长。
- 记录期间禁止下载历史文件或导出 MSC；MSC 导出期间不能开始记录。互斥由固件裁决，客户端处理 BUSY 与介质代次变化。
- MSC 应由用户点击“打开 U 盘”发起；交还时先停止磁盘访问并安全卸载电脑卷，再发 MSC_RELEASE，等待设备确认接管。插线/重连不自动导出。
- 最新固件说明列出 MSC 容量/挂载问题、发送侧丢弃未完全计入 lost、SAFE_STOP 与 MSC 所有权策略冲突、异常后档位状态污染等问题。可能正被其他会话修复，接续需重新核对；不得仅凭命令存在认为全部流程可交付。

### 5.3 客户端必须遵守的语义

1. 打开 CDC、置 DTR、HELLO 握手，读取身份、启动标识、会话、能力，再建立状态视图；端口名不当作设备身份。
2. ACCEPTED 仅表示受理，不能显示为已经开始/结束/交还成功。
3. 请求去重、版本冲突、重连与重试遵守协议；重连先查询，不自动重放此前未获回复的启动动作。
4. 新会话重建订阅；同时检查 sequence、lost、质量位、新鲜度和代次。lost=0 当前不足以单独证明无传输缺口。
5. 文件分页/句柄/分块读校验 media_generation；掉卡、换卡后不继续使用旧句柄。
6. 原始 BIN 校验版本、布局与 CRC，表达未正常结束、已知丢失及未知丢失；不能静默修补为完整数据。
7. 不改已有外设/硬件决定；无温度传感，不承诺温度补偿；等级阈值由试件实测提供。

## 6. 慢测试优先的交付建议

先做模拟设备/历史文件的编解码和状态恢复验证，再接真实设备；以一场完整慢测试作为首阶段验收主线。

建议覆盖：无卡监测、基线/配置缺失、按键发起记录后中途接电脑、联机启停、断线后继续记录与重连、定时结束（如选用）、下载/重新导入、BIN/CSV 对照、无效与缺口显示、异常文件及换卡。Windows 实机验证安装、USB、拔插和文件流程；Ubuntu 用于日常开发与辅助验证。

慢测试的时长、性能和稳定性数值尚未确定；不能用短时高速测试替代长时慢测试验收。快测试在慢测试完整流程通过后另行定性能指标与验收方案。

架构上建议分开连接/协议、设备会话、记录文件解析、试验本地管理、分析、界面；保留独立设备身份，方便未来扩展。此处不预设语言、GUI 框架、数据库或插件系统。
