# 固件工作模式与 CDC 通信规则（固件设计评审版）

主要读者为固件开发者、固件评审和接续工作的 agent。负责人从[设备行为与验收](../spec/device-behavior.md)开始，客户端开发从[上位机接入指南](../protocol/host-integration.md)开始。

本稿规定固件如何实现设备行为。当前没有上位机。现有固件的 ASCII CDC 入口见 [drms_cdc.c](../../firmware/DE-DRMS-Code/Core/Src/drms_cdc.c)。正式 CDC 采用二进制协议，USART1 用于独立调试。CDC 正式版直接启用二进制帧，不在运行时猜测 ASCII 或二进制；迁移现有固件诊断脚本时应显式选择接口。

本文只规定固件行为。资源集合、记录样本边界与持久化事务沿用[固件架构的 R1–R8、C1–C6](2026-11-05-firmware-architecture.md)，介质交接沿用 [MSC 设计](2026-11-05-msc-design.md)。表中的动作名用于讨论，不分配线上命令号。

## 1. 设备状态与裁决

状态快照分别表达采集、记录、介质健康、介质所有权、维护操作及连接会话。LED、按键和 CDC 读取同一业务状态。LED 映射、GPIO、USBX 回调和线程优先级均由固件内部管理，不能成为外部命令的参数。

| 动作或事件 | 设备承诺 |
| --- | --- |
| 上电、唤醒、复位 | 初始化后进入样品监测，稳定前输出无效。无卡也可测量。没有可用 R₀ 或区间表时分别报告原因，仍可提供有效电阻。开机及重新插卡均不恢复上次记录。 |
| 开始记录 | 测量键或 CDC 明确发起。控制模块原子预占资源，检查监测和本机可写介质。文件就绪且确认起始样本边界后才发布记录中。记录期间锁定采样参数、R₀ 和校准。 |
| 结束记录 | 按键、CDC 或定时到期作用于当前记录。定时时长用单调时间。确认末端样本边界、排空并关闭刷新后才发布最终结果。明确区分文件完整关闭与采样是否有损失。结束后继续监测。 |
| 开始与结束交错 | 按键手势在控制入口解释；CDC 分别表达开始与结束。并发开始至多产生一个记录会话。启动中收到结束须能取消或收尾，迟到的开文件或 DMA 回应不能重新激活已结束会话。 |
| 读取历史数据 | 记录启动、写入和收尾期间均拒绝下载和导出。显式导出后只读 MSC 才报告介质就绪。导出期间监测、CDC 状态查询继续，本机文件访问互斥。释放时等待在途读完成后再挂载 FileX。 |
| 建立 R₀、校准、配置 | R₀ 与仪器校准为不同操作，均允许无卡执行，遵守维护互锁。新 R₀ 与其依赖的运行配置一起持久化成功才发布。只有 CDC 可修改用户配置，设备区分运行值和已保存值。 |
| 拔卡、断线、安全停止 | 卡故障终止依赖卡的业务，仍有效的监测继续。CDC 断开清理会话资源，本机试验继续。USB 挂起本身不释放已导出的卡。安全停采或关机可从任何状态请求，有界收尾，超时报不完整。 |

### 1.1 首轮重构约束：操作完成与记录资源释放

控制模块统一受理按键、定时和 CDC 的动作，对外发布操作结果并管理资源占用。记录模块是记录状态的唯一写入者；采集模块确认起止样本边界 B/E，存储模块确认文件和在途 I/O 的实际结果。各读者从已发布的快照取数。

| 标识 | 分配与有效范围 |
| --- | --- |
| 请求号 | CDC 客户端在连接会话内分配，用于去重和关联回复。按键、定时器无需生成 CDC 请求号。 |
| 操作号 | 固件为每个新受理的动作分配。开始与结束分别有操作号，查询或复制结果不会清除资源占用。 |
| 记录号 | 固件在接受新记录时独立分配，非零，在一次启动内单调递增且不复用；耗尽则拒绝新建。禁止从请求号或毫秒计数派生。重连后以设备身份、启动标识、记录号定位同一试验。 |

| 时点 | 结果与资源归属 |
| --- | --- |
| 开始受理 | 控制模块以本次记录为单位原子预占 ACQUISITION_CONFIG、RECORD_SESSION、TF_ACCESS，再投递工作。尚未投递即失败可回滚；已有在途工作则进入取消确认。 |
| 文件就绪且 B 已确认 | 记录模块进入 ACTIVE，控制模块将开始操作归结为 OK。三项预占继续归本次记录；后续结束或取消使用已有预占。 |
| 启动中取消 | 锁存取消，作废本次启动代次的就绪通知；迟到回调只能参与清理。关闭已建的预备文件，禁止其作为成功试验发布。正常取消时开始操作为 CANCELLED；发起结束的操作在清理确认后完成。 |
| 正常结束或发生故障 | 记录模块汇总 E、末端数据排空和存储关闭结果。控制模块发布结束操作和记录摘要，分别报告文件关闭质量与采样损失。某项资源只有在对应的记录访问、缓冲引用和 I/O 均已退出后才可释放；无法确认则隔离并保持冲突请求被拒。监测本身可以继续。 |

实现检查：现有 `drms_control_complete()` 同时登记结果并处理资源释放。接续实现须提供可独立执行的“完成动作”和“按记录归还资源”两种语义。不得在 B 到达时以全部资源已静止调用该函数，也不得扣住开始操作的结果直到文件关闭。

**从实际控制入口验收：**

1. 延迟建文件完成，在 STARTING 发起结束，再交付旧就绪通知。记录始终不能转入 ACTIVE；开始与结束各有可查询的最终结果，预备文件已关闭或相关资源被明确隔离。
2. 延迟最后一次存储完成，同时请求下一场记录和 MSC 导出，均返回 BUSY。确认收尾后立即开始第二场，应获得新记录号；注入无法确认静止的故障时，仍须拒绝冲突操作。
3. 按键开始后，中途连接、查询、断线再连接。两次快照均能定位同一记录号，查询不推进算法，断线不截断采集和写卡。同一请求重发也不新增记录号。

## 2. CDC 请求与状态

1. 握手返回稳定设备标识、启动标识、连接会话标识、协议版本、当前固件实际支持的能力和传输上限。设备身份跨重启稳定；启动标识用于识别重启；新连接不得接收发给旧会话的迟到回复。
2. 线上帧为标准 COBS 编码的“版本化头、载荷、CRC32”，后接一个零字节。接收按字节流拼帧，验证边界、解码长度、结构和 CRC 后才提交。空帧忽略；坏帧计数；溢出时丢弃至下一分隔符。单次 USB 读写长度与消息边界相互独立。
3. 所有改变状态的入口经过同一控制模块。响应区分立即拒绝、已受理和最终结果。记录操作另发布实际记录状态。拒绝原因至少可区分能力未实现、参数错误、介质不可用、资源忙、状态冲突及 I/O 故障。详细底层状态只作诊断。
4. 同一会话内按请求号去重。编号及内容均相同则返回原操作状态；同号异内容拒绝；已过缓存窗口的旧号返回过期。记录会话标识独立于 CDC 请求号，按键发起的记录也可查询。重连后先取快照，按记录标识核对，再决定是否提交新动作。
5. 故障和操作结果优先于普通状态、曲线和大块数据；只在帧边界切换，发送完成后才复用缓冲。读取暂停或发送队列满时，本机采集、写卡和安全停止仍可运行。设备保留可查询的关键结果；流数据发生丢弃时向读者报告缺口。
6. 字段号、类型、单位及错误码发布后固定。可选扩展须可按长度跳过，未知必需字段明确拒绝。线上帧、BIN 和 Flash 快照分别版本化。升级仅列入规划，实际具备能力前不向客户端宣告支持。

## 3. 无上位机时的验收设计

后续可用字节流测试程序驱动正式 CDC 入口，用可控采集、时钟和存储替身检查业务结果。USB 枚举、挂起恢复、真实拔卡与吞吐另做实板验收。

| 场景 | 通过条件 |
| --- | --- |
| 无卡启动 → 插卡 → 按键记录 → 电脑连接 → 断线 → 定时结束 → 再次记录 | 插卡不建文件；连接可查到按键发起的记录；断线不截断试验；自然结束有明确结果；第二次记录获得新标识。 |
| 同一开始请求重发，同时发生本机开始意图 | 至多一个记录会话、一次建文件。重复请求返回原操作结果，竞争请求有明确结论。 |
| 丢失受理回复后重连，或设备已复位 | 同次启动可查询当前记录及留存结果。已复位可由启动标识识别。两种情况均不自动重放开始动作。 |
| 任意位置拆帧、多帧合并、超长帧后跟有效帧、CRC 错误 | 合法命令各执行一次；坏帧没有业务副作用；后继有效帧可处理。 |
| 写卡中请求 MSC；MSC 读取中拔线；收尾期间拔卡 | 无双重介质所有权；在途读取退出后才允许重新挂载；收尾失败可查询且不会显示正常保存。 |
| 主机停止读 CDC，随后发生存储故障或安全停止 | 本机处理故障或停止的进度独立于 USB 发送；恢复通信后可查询结果。 |

## 4. 正式接口与版本

[CDC v2 线格式及工作流](../protocol/de-drms-cdc-v2.md)和[机器字段表及向量](../../shared/protocol/de-drms-cdc-v2.json)是本设计的外部契约。现有 v1 ASCII 说明继续描述旧固件。正式版本只在 CDC 运行 v2，诊断走 USART1。BIN v1 继续可读；v2 写入须验证生产记录入口确实调用[对应格式](2026-11-06-record-v2-format.md)，文件解码按自身版本。升级只预留维护能力和分区保护，不发布可用命令。

## 5. 本机操作与提示

以下按键时长及灯效是首版交互设计值，可用注入时间验证，首板另验收手感和可辨性。两键各自消抖，每 10 ms 读取，电平稳定 50 ms 生效；启动按住须先释放。短按只在释放时产生一次，长按满 2 s 产生一次且吞掉本次释放，不启用双击。两键并发时电源安全请求优先，同轮冲突开始动作取消。

| 输入 | 行为 |
| --- | --- |
| 测量键短按 | 已停止时恢复监测，本次按键只恢复；监测就绪时请求记录；启动中或记录中请求结束；收尾中只提示忙。无卡或处于导出时提示具体原因，监测继续。采集故障先检查后端能否安全恢复。 |
| 测量键长按 | 主动建立试件 R₀，保持现有配置直到质量合格且快照持久化成功。记录期间返回忙。绝不因为拿到第一笔数据便自动建基线。 |
| 电源键短按 | 安全停采并收尾，不进入待机。 |
| 电源键长按 | 电池运行时请求关机；满足硬件安全条件且松键稳定后进入 Standby。VBUS 在线抑制待机，若在收尾期间接入 USB，只取消待机，已经结束的记录不恢复。保留调试用软件 USB 断开/重枚举，不能通过切整机供电模拟拔线。 |
| 电池保护 | 沿用现有策略，仅电池供电且读数有效时，≤3650 mV 提示，连续五次秒级有效读数 ≤3500 mV 请求有界关机。外部供电或无有效电压清连续计数。收尾超时锁存未完整原因；无法确认 DMA 静止时先执行安全抑制及隔离。 |

PWR 灯独立表达运行状态：普通运行常亮、记录中每秒短灭 100 ms、收尾用 250 ms 等间隔亮灭、待机熄灭。四个等级灯用 PCB 逻辑顺序 L0..L3（PB13、PB14、PB15、PC6），不用颜色作为唯一识别手段。CONFIRMED 且 fresh 时只点亮对应等级。待确认以四灯同步短亮 100 ms/秒；无基线、未配置、过期或无映射时不点亮正常等级，均以四灯每两秒同步双短闪表达“暂无可用等级”，具体原因从状态读取。维护时四灯顺序移动，每步 150 ms；故障时四灯同步 250 ms 亮灭。优先级为故障、维护、操作反馈、监测；被拒操作四灯同步三次 100 ms 亮/100 ms 灭，随后恢复当前状态。记录与等级通过不同灯同时表达。所有效果由同一慢速线程随单调时间推进。

## 6. 固件组织和 CubeMX 边界

目标目录均在 firmware/DE-DRMS-Code 内，沿用一个固件构建目标。职责四层，外加一个组装入口。依赖规则检查直接和传递头文件；硬件回调向上报告事件时同样遵守此边界。

| 位置 | 所有权与允许依赖 |
| --- | --- |
| App/interfaces/{local_ui,cdc,debug} | 手势、灯效、会话、信息编码。调用业务公开请求/查询接口及窄 I/O 接口。不能取写卡句柄或触碰 ADS 寄存器。 |
| App/application/{control,measurement,recording,settings} | control 拥有资源预占与业务裁决；measurement 拥有换算、质量、滤波及区间；recording 拥有样本边界与会话；settings 拥有版本、R₀ 及持久化事务。公共接口只暴露值、标识、只读快照及明确所有权的固定块。 |
| App/ports | 采集/时钟、存储、配置提交、传输和板级 I/O 的最小契约。纯 C 类型；一个 public 定义维护一处。已冻结的 drms_architecture_contract.h 迁移只挪位置，旧 include 有消费者时保留转发头。 |
| App/platform/{stm32,threadx,filex,usbx} | 设备与中间件适配。实现 port，持有 HAL/RTOS 句柄；不包含具体业务模块私有头。ISR 只使用明确标为 ISR-safe 的端口。 |
| App/bootstrap | 唯一接线位置。实例、线程、队列和适配器从这里组装；生成入口的 USER CODE 调用薄启动钩子。业务和平台均不引用 bootstrap。 |

各模块源和私有头就近放置。业务间经公开契约通信，控制线程不得持锁同步等待其他线程。算法不引用 HAL、ThreadX、FileX、USBX。跨层事件用固定大小值或块描述符；绑定和回调不引入逆向头文件依赖。对照现有代码，先把 drms_application 中的按键、分发、边界和快照职责辨清，按功能切片迁移；每片使用相同外部输入比较状态与输出，行为修复与纯移动分别提交。

Core、Drivers、Middlewares、AZURE_RTOS、FileX、USBX 由生成器管理。自有源码/包含目录只维护一份显式构建清单；Makefile 与 postgenerate 共用清单，禁止两个同名源文件生成同一目标。启动胶水留在 USER CODE，已有厂商补丁由已知模板恢复器维护。验收在工程副本中通过 CubeMX Generate、运行 postgenerate --apply、再次只读检查、全量构建及 map 核对；再执行第二轮，差异必须可解释。未知生成模板立即失败。正常用户修改的 IOC 参数必须保留，不能用回拷固定 IOC 恢复工程。

## 7. 调度、所有权和故障

- 采集 ISR → 原始环（4096×16 B）→ 测量处理 → 记录环（32768×16 B）→ 存储线程（32 KiB staging）。每环一个生产者和一个消费者。USB 使用独立小块；ISR 不编码、不写文件。真实 DRDY 时间下界用 65×32 B 侧表，名义采样时间供算法使用。每 10 ms 检查新鲜度，即使没有新样本也可撤销正常显示。
- ThreadX 控制线程处理请求、完成和安全锁存；采集及处理按事件分批；FileX 线程独占介质；CDC RX 与单发送者 TX 分离；USB 管理维护连接代次；按键与灯效共用慢任务；电池、诊断和 UART 调试按低频/有界工作。允许慢服务共线程，阻塞 USB 或 SD 的调用须留在专属上下文。保留系统定时器和 USBX 内部线程的调度预算。
- 设备控制一次取得 C2 资源集合，安全停止保留独立通道。存储和 USB 完成通知带代次。超时后进入有界 abort/recover，确认静止才可复用 DMA 缓冲；不能确认则隔离，故障清除必须有真实恢复证据。看门狗按启用任务的实际进展监督，合法空闲也要能区分。
- 记录启动/结束采用 C1 的 B/E 生产者边界，消费者屏障期间继续处理控制与新鲜度。记录最终结果分别报告 clean_end、已知丢帧数及未知损失；不因完成通知丢失永久占用预留资源。状态一致发布，M33 上的 64 位值通过短临界区或序列快照读取。
- 线程优先级及栈以[实施记录中的线程清单](2026-11-06-firmware-architecture-plan.md)为现状基线。目标优先顺序先满足硬件捕获、安全控制和存储排空，再为 USB 和慢任务留出执行时间。压力运行必须验证处理和存储都能前进。主 RAM 占用 ≤736 KiB，保留 ≥32 KiB；每个栈余量至少 max(256 B,25%)。静态池、线程、协议重试缓存不得重复计数或漏计。每个速率分别验证监测、记录和上传组合，再公布能力。
- 电源、卡和采集分别计故障。卡错只结束依赖卡的业务；采集质量不满足时撤销有效等级；USB 慢读或断线只影响会话。正常信息约每秒更新，严重故障立即锁存，可查询后再安排通知。上电和掉电后不回放动作。

## 8. 配置、记录和以后升级

运行配置、已保存版本、仪器校准及试件 R₀ 分别标识。Flash 末端 32 KiB 固定：用户 A/B 从 0x080F8000、0x080FA000 开始，校准 A/B 从 0x080FC000、0x080FE000 开始，每页 8 KiB。提交前校验版本、写备用副本、校验后提交；任一步掉电只能恢复完整旧版或完整新版。用户恢复默认不擦仪器校准；不认识的新版本保留原始记录并报告不兼容。重配置后重建滤波和采集代次，R₀ 按其依赖判定适用性。阈值和质量参数没有依据时报告未配置，允许单独读电阻，不发布客户等级。

未来 CDC 升级使用独立 Bootloader、小块下载、独占维护、镜像校验及恢复入口。当前版本不分配升级命令、不承诺回滚；待有实际镜像大小、暂存布局和真实性验证方案后独立评审。应用、暂存和安装路径均不得覆盖配置区；该项不阻塞监测、记录和正式控制协议。
