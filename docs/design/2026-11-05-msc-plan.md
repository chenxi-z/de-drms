# 只读 MSC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留 CDC 和采集能力的同时，安全地将 TF 卡作为只读磁盘导出。

**Architecture:** 存储线程保持介质唯一所有者，MSC 回调通过有界请求访问它。
导出前关闭 FileX，释放导出时等待在途读完成，再重新挂载。

**Tech Stack:** C、ThreadX、USBX、FileX、STM32U5 HAL、Python unittest、ARM GCC。

**Spec:** [已确认规范](2026-11-05-msc-design.md)

## Global Constraints

- 不改 IOC、EDA、历史仿真或已有 BIN 布局。
- CDC 保持可用；MSC 只读；记录中拒绝导出，导出中禁止所有记录入口。
- 不在中断上下文执行 SD 或 FileX 操作；只有存储线程操作 TF 外设。
- 逻辑扇区 512 字节，FIFO 总量不超过 320 个 32-bit 字。
- 队列有界；超时不能导致仍在使用的缓冲或请求槽被复用。
- 不实现新二进制协议、R₀、分档或实时数据订阅。
- 当前工作区大量文件已有用户修改；仅提交本任务明确拥有的改动，不打包用户文件，不推送。

## Review Focus

- 导出接受与按键启动同一时刻发生：记录只能被接受一次且不能穿过导出屏障（任务 1、4）。
- USBX 读超时后晚到完成：旧代次不能写入新请求缓冲（任务 2）。
- 换入不同容量卡：旧容量与旧请求不能用于新介质（任务 2、3）。
- reset/unconfigure/物理断线发生在读取中：撤销就绪并排空后再挂载（任务 3、4）。
- CubeMX 重生成恢复了可写默认值：保护检查应拒绝验收（任务 5）。

- 修改 `drms_command.c/.h`、`drms_application.c`、`drms_console.c`、`FileX/App/app_filex.c`：调试命令、状态、所有记录入口互锁及存储服务。

### Task 1: 导出状态及记录互锁

**Interfaces:** `int drms_msc_request_export(void)`、`int drms_msc_request_release(void)` 返回接受/忙/未就绪；
`int drms_msc_blocks_recording(void)` 查询互锁；`void drms_msc_service(void)` 仅存储线程调用。
状态使用规范中的五个值，错误独立；对外头文件明确枚举，值发布后不复用。

- [ ] 先添加生命周期失败用例；断言 `export_accepted => recording_rejected`，LOCAL 且卡可用时记录仍能开始；记录 state=1/2/3 均拒绝导出。
- [ ] 运行 `python3 -m unittest discover -s test -p 'test_msc_lifecycle.py' -v`，确认因缺失生产实现失败。
- [ ] 实现原子请求接纳与重复请求规则；应用线程和按键共用记录互锁，存储线程复查后才 flush/close；覆盖转换中反向请求和 flush 失败。
- [ ] 运行该测试及 `test_application.py`、`test_storage_lifecycle.py`，确认通过后审查任务差异，只提交本任务自有文件。

### Task 2: 存储所有者中的有界读取

**Interfaces:** `int drms_msc_read(uint32_t lba, uint32_t blocks, uint8_t *out)` 是 USBX 线程同步入口，
不直接访问 HAL；任务 1 的 service 消费请求。`void drms_msc_cancel(void)` 撤销就绪并请求排空；
`int drms_msc_media_info(uint32_t *blocks)` 只在已导出时提供当前容量。

- [ ] 添加用例：最后一个合法扇区内容正确；`lba=UINT32_MAX, blocks=2` 拒绝；读超时后的旧完成不能覆盖新请求；清理前必须确认在途读结束。
- [ ] 运行任务 1 的测试文件，确认上述新增行为失败。
- [ ] 实现单在途邮箱、对齐专用 512 字节缓冲、代次及取消确认；轮询读每扇区有界等待，初始超时 1000 ms；每步检查掉卡和取消并让出 CPU。调用方总等待按块数有界计算，超时后不重用未确认释放的槽。
- [ ] 导出使用已关闭 FileX 的 SD 外设；重新初始化保留 24 MHz；读取卡实际逻辑容量。释放时先撤销就绪、排空读、deinit，再挂载 FileX。
- [ ] 测试读错误、初始化失败、掉卡、无卡、卡容量变化、重新挂载失败和关机等待，全部通过后审查并仅提交本任务改动。
