# CDC + 只读 MSC 设计

状态：原规格已讨论确认；2026-11-06 所有权规则修订待复核。本文件不是已实现功能声明。

内部实现遵循[架构规格 R4/R5](2026-11-05-firmware-architecture.md)：介质所有权与健康分离，取消不能确认静止时隔离。下文 ERROR 为外部兼容状态，不作为内部资源所有权；本次修订优先于旧状态表。

## 目标与范围

用户决定先完成 MSC。USB 同时提供 CDC 控制口与一个可移动磁盘逻辑单元。
磁盘只读，电脑可以复制 TF 文件，不能写入、删除、格式化。
正常监测和记录时磁盘报告介质未就绪；用户显式导出后才允许电脑读取。
导出期间保留采集和监测能力，禁止本机记录及 FileX 文件访问。
记录正在打开、写入或关闭时拒绝导出，不自动停止试验。

本轮不实现新的二进制协议、R₀/分档、实时数据订阅或文件下载。
现有采集、校准、记录格式与命令含义保持兼容。

## 当前工程证据

- IOC 已开启 CDC、MSC，设备类数量为 2。
- CDC：IN 0x81、OUT 0x01、通知 IN 0x82；MSC：IN 0x83、OUT 0x04。
- MSC 回调目前是空模板，读写/状态返回成功，容量和块大小返回 0。
- 现有 FIFO 只覆盖 CDC；原有生成恢复脚本已恢复四处 SDK/初始化修复。
- FileX 线程现为 TF 介质所有者，日志线程行为在该线程中执行。
- 本设计以当前 STM32U575RGT6、HSI48/CLK48、SD 24 MHz 为边界，不修改 IOC。

## 状态与操作

外部公布 LOCAL、EXPORTING、EXPORTED、RELEASING、ERROR 五种状态。
介质就绪只在 EXPORTED 且卡有效、USB 已配置且本轮导出代次一致时成立。
状态和最近错误分别公布，不能用 ERROR 掩盖卡仍由哪个线程负责清理。

暂以兼容现有调试控制口的命令 `MSC EXPORT`、`MSC RELEASE` 接入。
请求先返回接受或拒绝，最终状态通过 STATUS 中新增的 msc_state、msc_error 查询。
沿用现有排队命令的结果机制，不宣称已具备未来二进制协议的去重和会话保障。
同方向重复请求不重复操作；转换中相反方向请求返回忙。
USB 未配置、无卡、关机请求或记录非空闲时，EXPORT 返回明确失败。
导出不持久化，重启默认 LOCAL，不自动导出或自动开始记录。

### 进入导出

1. 在应用命令和记录启动入口建立互锁；一旦接受导出，立即拒绝新的记录启动。
2. FileX 所有者再次检查记录空闲，flush 并关闭介质；失败则终止导出并报告错误。
3. 确认 FileX 驱动及其 DMA 已释放，再初始化供原始读取使用的 SD 访问。
4. 获取实际逻辑块数量，校验 512 字节块及合法非零容量；最后 LBA=块数−1。
5. 更新 USBX LUN 容量，再发布介质就绪，通知介质变化；CDC 不重新枚举。

### 退出导出

1. 先撤销介质就绪、禁止接收新读取，并增加导出代次。
2. 在途读取完成或超时取消后，等待存储所有者确认不再访问其缓冲。
3. 释放原始 SD 访问，再让 FileX 重新挂载；挂载失败保持不可记录并报告原因。
4. 解除导出互锁，但不自动开始记录；监测不因退出导出而停止。

CDC 命令 RELEASE 或物理拔 USB 都发起上述退出流程。
USB suspend 不释放 TF 所有权；恢复后继续原导出状态。
USB reset/unconfigure 撤销介质就绪并请求释放；不在 IRQ 中做介质操作。
电脑的“弹出”不作为唯一退出入口；即使主机未正确弹出，也必须能安全处理断线。
主机发出的介质弹出请求不得自行绕过存储所有者切换状态。

## 线程与读请求归属

存储线程是唯一能够切换 TF 状态、初始化/释放 SD 和调用 SD 读接口的线程。
USBX MSC 线程只提交有界的读请求并等待结果，不直接操作 FileX 或 SD。
最多一笔在途请求，使用专用对齐扇区缓冲和请求代次，不借用 USBX 接收缓冲进行异步 DMA。
请求按 512 字节扇区分步处理，成功后才复制给 USBX；每步检查卡、代次与取消状态。
原始 SD 访问使用有超时的轮询读，保持现有 FileX DMA 回调/信号量归属不变。
存储线程在读请求之间让出 CPU，不能用长时间关中断保护介质切换。

超时必须同时解决请求和缓冲所有权：调用方超时后不能立即复用仍由存储线程使用的请求槽。
退出导出必须等待在途操作确认结束，不能仅靠一个状态变量就重新挂载 FileX。
移除介质时不 flush 已拔出的卡；取消请求、释放外设、增加代次。
导出期间重新插入卡不自动替换当前磁盘，要求完成释放后重新请求导出。

## USB 与 SCSI 行为

- 逻辑扇区大小始终为 512；无卡启动不允许零块大小，不要求有卡才能初始化 CDC。
- 注册时使用安全的非零块大小；未导出时容量不代表可访问介质。
- 实际导出容量以当前卡信息为准，替换卡后不能沿用旧容量。
- LBA 与块数用减法校验范围，拒绝溢出、越界及非法 LUN，不截断成合法请求。
- 写保护同时体现在 LUN 标记和写回调；写回调返回 DATA PROTECT，不触达 SD。
- 未导出/掉卡返回 NOT READY；读失败返回合适的介质/硬件错误，不能返回伪成功。
- 不支持的通知返回明确的不支持状态或合法空响应，不能返回未初始化指针和长度。
- 必须检查当前 USBX READ CAPACITY、TEST UNIT READY、START STOP 和读写路径实际如何消费回调，
  使所有访问都受相同介质就绪和代次检查约束；必要的 SDK 适配纳入生成后恢复工具。

FIFO 使用总量不超过 320 个 32-bit 字的配置，建议 RX=128、TX0=32、TX1=64、TX2=16、TX3=64，
合计 304；最终按 SDK 的最小 FIFO 要求及回归结果确认。
MSC OUT 端点 4 使用共享 RX FIFO，不额外分配 TX4。
类注册失败、FIFO 配置失败都禁止附着；检查双类内存池和线程创建结果。

## 安全与关机

本机按键和通信命令所有记录入口均受导出互锁约束，不能只限制控制口 RECORD。
STOP 可继续停止采集，但不会默默将 TF 从电脑收回。
关机先撤下 MSC 介质、取消并排空读请求，再完成 SD 清理和既有关机流程。
USB 已在线时保持现有取消关机策略；迟到的 USB 事件仍需走原有竞态保护。
导出失败不得影响 CDC 查询故障，也不得将未关闭的 FileX 与 MSC 同时启用。

## 生成与兼容边界

应用逻辑置于独立 drms 模块，生成文件仅在 USER 区接入。
非 USER 区若确需修改，更新 firmware_postgenerate.py，加入识别、恢复与未知模板拒绝测试。
只读标记、双类数量、端点与 FIFO、MSC 回调不能被重新生成静默回退。
控制口新增字段和命令时，同步 shared/protocol/de-drms-v1.json 与 docs/protocol/de-drms-v1.md。
不改历史 BIN 文件布局，不修改 EDA、IOC 或历史仿真结果。

## 验证与完成标准

主机测试编译真实生产模块，替换 HAL/ThreadX/介质边界，覆盖：

- 无卡启动、两类注册和端点/FIFO 配置，MSC 失败不伪装成就绪。
- 记录中拒绝导出，导出接受后阻止所有新记录入口，CDC/采集保持运行。
- flush/close/初始化/容量查询任一步失败不开放磁盘，不存在双重管理 TF 的窗口。
- 实际扇区内容、首末合法 LBA、越界/溢出/非法 LUN，以及只读写拒绝。
- 读超时、退出时在途请求、掉卡、拔 USB、reset、重新插卡，旧代次不能污染新请求。
- 主机介质访问路径的状态与容量检查；SDK 如有补丁，测试实际 SDK 源码。
- FileX 重挂载和记录恢复、关机、生成后恢复幂等、全量旧回归及 ARM 构建。

实板验收另行进行：Windows/Linux 枚举 CDC 与磁盘、复制文件内容比对、写入/删除/格式化拒绝、
插拔/挂起/恢复、换卡容量刷新、采集中导出与退出、连续复制和异常拔线。
主机替身测试和构建成功不能声明上述实板项目已经通过。
