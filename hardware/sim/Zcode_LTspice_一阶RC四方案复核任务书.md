### 特别核对 ADC 实际连接

ADS131A02 为**2 路同步差分**采样：

- `AIN0P`：测量 T 节点，经 OPA388；
- `AIN0N`：测量 M 节点，经 OPA388；
- `AIN1P`：测量 B / Rsense 顶端，经 OPA388；
- `AIN1N`：Rsense 底端 E / Kelvin 地，**不经过第四颗 OPA388**。

因此共有 **3 颗 OPA388** 而不是 4 颗。`AIN1N` 需要保留真实的接地回路/源阻抗及 RC 接法；请勿把四条线全部改成理想对称运放输出。完整通道归一化以及 `Vsample/VRsense` 测量必须按实际接线。

## 2. 四组待测方案：必须全部跑完

保持同一个一阶差分结构：

```text
前端驱动 P ─ R_P ─●───────── ADC AINxP
                  │
                 C_GP
                  │
                 AGND

                    C_D
           AINxP ──||── AINxN

前端驱动 N ─ R_N ─●───────── ADC AINxN
                  │
                 C_GN
                  │
                 AGND
```

为避免 ASCII 图歧义：**每条输入线各串一颗 R、各有一颗对地 C_G；C_D 仅跨接 ADC 的 AINxP 与 AINxN，位置在串联电阻之后。** 每个差分通道共 2 R + 2 C_G + 1 C_D = 5 件；两个通道共 10 件。所有器件值对两个差分通道一致，仅角差/容差测试时偏移。

| ID | 方案 | 每线 R | 每线对地 C_G | 每差分通道 C_D | 面积假设 | 说明 |
|---|---|---:|---:|---:|---|---|
| `FO1_BASE` | 原始基线 | 47 Ω | 47 nF | 820 pF | C_G 为 1210；C_D 为 0603 | 作为回归校验，不可跳过 |
| `FO1_A` | **首选待证** | **100 Ω** | **22 nF** | **820 pF** | C_G 暂按 0805；C_D 为 0603 | 差模/共模时间常数都接近原方案 |
| `FO1_B` | 0603 保留 Cd | **200 Ω** | **10 nF** | **820 pF** | C_G、C_D 都可考虑 0603 | 需格外检查 ADC 负载、kickback、失真 |
| `FO1_C` | 0603 改差分 C | **100 Ω** | **10 nF** | **6.8 nF** | 两类 C 均考虑 0603 | 差模接近，但共模截止频率显著变高 |

**器件库存/封装都是待核实的采购假设**，不能以此表代替 BOM 验证。尤其检查 22 nF/0805、10 nF/0603、6.8 nF/0603 的实际 C0G/NP0 料号、耐压、SRF/阻抗曲线、容差、焊盘面积。若 22 nF 0603 C0G 真实可得，可以额外增加 0603 子变体，**但不可替代上述四组必测**。

### 理想 RC 自检基准（不是 LTspice 验收真值）

使用下式，差模与共模**分别**检查：

\[
C_{\mathrm{DM}} = C_G+2C_D,\qquad
f_{c,\mathrm{DM}}=\frac{1}{2\pi R(C_G+2C_D)},\qquad
f_{c,\mathrm{CM}}=\frac{1}{2\pi RC_G}
\]

| ID | 理想差模 fc | 理想共模 fc | 理想差模衰减 @16 kHz（约） |
|---|---:|---:|---:|
| FO1_BASE | 69.62 kHz | 72.05 kHz | −0.224 dB |
| FO1_A | 67.32 kHz | 72.34 kHz | −0.239 dB |
| FO1_B | 68.37 kHz | 79.58 kHz | −0.232 dB |
| FO1_C | 67.44 kHz | 159.15 kHz | −0.238 dB |

这些数基于理想对称 RC 且忽略 ADC 输入负载、运放闭环输出阻抗及 PCB 寄生。若实测偏离较大，**首先检查接线、单位、模型、激励归一化与测点**，不能为了对齐数值修改仿真数据。

## 3. 模型、激励和计算口径

### 3.1 主仿真模型

- MCU/采样链工作目标：`fCLKIN = 16.384 MHz`，ADC `fMOD = 4.096 MHz`，输出 `128 kSPS`，`OSR = 32`。
- ADC：**ADS131A02**（不要与 ADS131M02/M04 混淆）。
- ADS131A02 参考：内部基准约 `2.442 V`；手册中 ADC 输入采样电容 `C_S≈3.5 pF`（差分）、输入等效阻抗 `Zin≈130 kΩ typ`。**均需核对现有设计文档及官方手册的适用条件**。
- 采样开关模型的 `Ron` 未由文档确证：只允许作为**声明过的参数假设**扫值，不得称为手册实测。
- 缓冲器：使用真实 **TI OPA388 SPICE 宏模型**。切忌只用 0 Ω 理想源给出最终结论。
- 真实完整链路包含恒流源、Rsense、OPA388、AIN1N 的 Kelvin 地路径；沿用工程已有拓扑。
- 频率扫描建议：`0.1 Hz ~ 100 MHz`（必要时分段加密），保存 8 kHz、16 kHz、64 kHz、128 kHz、4.096 MHz、16.384 MHz 的精确插值值。
- 工况：常温标称先跑，再运行供电、输入共模、源阻抗、R/C 容差等角点；高源阻抗样品工况须涵盖 600 kΩ（若工程实际模型另有限值，记录来源）。
- R 容差参考 ±1%，C0G 电容容差参考器件真实规格（优先 ±5%，另跑 ±1% 目标/配对方案），不要默认所有电容零误差。

### 3.2 三层结果不得混为一谈

对每种方案分别输出：

**层 L1（理想无源网络）**：确认拓扑/截止频率/幅相。

**层 L2（模拟实际网络）**：OPA388 / 恒流源 / ADC 等效电路，测 ADC 引脚前的模拟信号，完成原 D1–D10 口径。**D4 仅评价模拟段相对 DC 的通带衰减，不纳入 sinc³**，遵守原规格。

**层 L3（系统测量）**：考虑 ADC sinc³ 数字滤波、两测量通道比值 `R = (Vsample/VRsense)*Rsense`、扫频相位与高频可能折叠后的误差。可用离线 Python 按 datasheet 传递函数处理，但必须注明这不是 LTspice 直接包含 ADC 全数字内核的仿真。

对 ADC 的数字滤波，特别检查 **4.096 MHz 附近注入可能在采样阶段折叠回低频**：不能把“sinc³ 在数字域有阻带”当成 fMOD 附近模拟抗混叠已通过的证明。没有可信开关采样/数字滤波模型时，只给出有界风险与测试建议，不宣称“验证了混叠”。

### 3.3 比值和共模指标定义

要求输出以下复数频率响应及幅相：

- `H0(f)`：ADC CH0 差分输出 `V(AIN0P)-V(AIN0N)` 相对 CH0 对应模拟激励的传递函数。
- `H1(f)`：ADC CH1 差分输出 `V(AIN1P)-V(AIN1N)` 相对 CH1 对应模拟激励的传递函数。
- `Hratio(f) = H0(f)/H1(f)`：直接用于 V/I 比值链的相对幅频与相频误差；说明归一化定义，不能简单用不同幅度激励的两个原始电压相除。
- `H_DM(f)`：单个差分通道的差模输入→差模输出，记录幅度/相位。
- `H_CM→DM(f)`：共模输入→差模输出；定义 `CMRR_RC = 20log10(|H_DM/H_CM→DM|)`，必要时另列 CM→DM 抑制比。**不要把输出共模衰减 D2 误写为 CMRR D8**。
- 对真实 CH1 的 AIN1N Kelvin 接地结构，另给出“真实接线”结果，不能依靠假设的全对称 P/N 覆盖这一问题。

## 6. 自动化执行方法（Zcode 操作 LTspice）

1. **探测实际工具环境**：列出操作系统、LTspice 可执行文件和版本、模型库位置、Python 版本、当前 repo 路径。
2. **先执行现成基线**：直接运行工作目录现有 FO1 案网表/原图；记录原始曲线与结果，核验 `D1≈−40.7dB / D2≈−46.4dB / D3≈−62.7dB / D4≈0.230dB / t≈21µs / PM≈98.6°`。偏差明显时先排查测试口径，不得直接写“复现成功”。
3. **创建隔离目录**：如 `hardware/sim/signalchain/fo1_rc_review/`，避免覆盖旧 `.asc/.net/.raw/.log` 和生产图。
4. **克隆基线并参数化**：将每方案电阻、电容做成参数或网表副本；维持所有其余电路、模型、供电、激励、分析设置一致。
5. **批量调用本机 LTspice**：优先使用本机可用的批处理能力，支持 `.net` 时优先直接运行网表（既有计划注明 `.asc` 有时依赖 GUI 解锁）。**先查询本机 LTspice 版本的实际 CLI 支持**，例如支持时可采用 `LTspice.exe -b <netlist>`；`-ascii` 仅在本机版本确认有效时使用。若命令行不可用，Zcode 通过 UI 打开/运行并导出，记录步骤。
6. **结果解析**：`.meas`/`.log` 输出定量值；`.raw` 可通过 LTspice 导出文本/CSV 或经可靠解析程序处理。对复数 AC 结果要正确处理 dB、相位 unwrap、群延迟微分和幅度归一化。
7. **一致性校验**：同一方案抽查 `.raw`、`.log`、CSV 三者数值；独立 RC 理论基准用于发现错误但不能替代 LTspice 结果。
8. **异常处理**：仿真不收敛、模型缺失、数字采样模型不足、宏模型不支持 `.noise` 时必须标记并归因；先把其他项目跑完，再提出补救，而不是宣告全部通过。
9. **禁止误导**：不要自动复制历史三阶/四阶仿真数据冒充一阶；不要把 47Ω+47nF 的结果直接套给其他三组；不要只画图不导出可重复计算的数值。

`REPORT.md` 必须包含：
1. **结论摘要**：是否建议采用 `100Ω+22nF+820pF`，与其他方案相比的实测优缺点。
2. **回归表**：原 FO1 数值 vs 本轮 FO1_BASE 复测，所有明显偏差说明。
3. **四案总表**：D1–D10、C9、8k/16k 幅相、共模、Hratio、实际 CMRR、采样回稳、ADC 加载、噪声、PCB 占地、PASS/FAIL/NOT VERIFIED。
4. **方案排序**：原规格是否合格、面积约束下建议、牺牲了哪些指标。
5. **关键问题**：4.096MHz 附近混叠风险、AIN1N Kelvin 接地非对称、16kHz 双通道幅相误差、是否需要匹配/标定。
6. **数据证据**：每个重要结论的日志/CSV/图像/网表链接；显示运行命令或 UI 操作步骤。
7. **遗留/未测**：不隐瞒模型限制，清楚写出 PCB 寄生、真实 ADC THD、射频耦合、实物 EMC、温度实物测试等不能由当前仿真证明的项目。
